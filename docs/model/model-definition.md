## `seasonal-record` v1.1.0（現行）

feature 008。設計見 [008 research](../../specs/008-new-game-forecast/research.md) R1–R3，程式在
`src/sweetspot/forecast/models/seasonal_record.py`（`SeasonalRecordV110`）。預測什麼、見過與更深等級的結構都和 v1.0.0 相同（下一節），
只改兩件事；`low_base = population`、`shrink = 0` 時和 v1.0.0 逐位相同。

### 規則（和 v1.0.0 不同的部分）

1. **低信心（本身沒有已結束的季節特賣紀錄）**：不用全體遊戲每場的比例，改用**新遊戲前 k 場的經驗累積比例**。
   - 新遊戲序列：分析時點以前，參考資料集每款遊戲在目標區域已結束的季節特賣紀錄；第一場開始時距發行日不超過 365 天才算。
     發行日未知的遊戲不算。
   - F(k, d) = 至少有 k 場紀錄的序列中，前 k 場最大折扣 ≥ d 的比例；序列少於 30 個時沿用 k − 1；隨 k 不遞減、隨 d 不遞增。
     第 1 場就不足 30 個時，退回全體每場的比例並在原因中寫明。
   - `low_base = new-split`：目標在分析時點尚未發行時，用「第一場紀錄在發行日以前」的序列（預購）；其餘用已發行的序列。
     正式的 `forecast`／報告對尚未發行的遊戲只給 `unreleased` 狀態，所以預購序列只在回測中用到。
   - 信心仍為低。原因寫出發行日、序列數與「第 1 場達到 -d% 的比例」。
2. **見過的等級向全體比例收縮**：每場比例 p(d) = (n · p_w(d) + a · b(d)) / (n + a)，n 為本身紀錄數，a = `shrink`，
   b 為全體每場的比例（`seasonal-freq` 的整體比例）。紀錄越多影響越小；只有 1 場時「下一場 ≥ 那一場的折扣」不再是 100%。
   收縮後每一列依 d 取累積最小，保證不遞增。本身 ≤ 3 場而且改變 ≥ 1 個百分點時，原因多寫一行。
3. **發行日**：靜態的遊戲事實，框架一次讀取所有遊戲的發行日，放進證據與參考資料集（評分框架設定「發行日」）。

### 已知限制

1. **60–90% 的機率略偏保守**：只計已結束時，實際比預測高 3–4 個百分點（驗證組）。收縮讓紀錄多的遊戲的見過等級也略為下降。
2. **紀錄很多、剛好在過去最深的等級仍然低估**（6 場以上、下一場：預測 0.692 → 實際 0.811，調參組，v1.0.0 就有）：
   本 feature 只要求它不變差（008 spec clarify），之後的候選。
3. **發行日**：取最新已知的值（靜態事實）。發行日事後被改成較晚的日期時，已發行的遊戲會被當成尚未發行（資料庫中 1 款有不同的值）。
4. **發售前的季節特賣**：一般信心路徑仍把它們算進本身的紀錄（同 `seasonal-freq` 已知限制 8）；008 research R0.6 顯示影響少而方向不一致。
5. **美國區的預購序列樣本少**：美國區的低信心分開預購反而較差（調參組 0.1566 vs 不分開 0.1443）；台灣區是主要目標。
   美國區早期的分析時點新遊戲序列不足 30 個時，退回全體比例。
6. **美國區只計已結束時中段高估**（0.5–0.6：0.549 → 0.409）：1–5 年的長期預測，v1.0.0 也有（只計已結束 Brier 0.1132 → 0.0899）。
7. 其餘同 v1.0.0 已知限制 2–4。v1.0.0 已知限制 5（只有 1 場時見過的等級直接照那一場）由收縮處理。

## `seasonal-record` v1.0.0

2026-09-26 到 2026-09-27 的現行模型（feature 004），保留在程式中（`seasonal-record@1.0.0`）。以下是它當時的定義與回測。

feature 004。設計見 [004 research R1](../../specs/004-deeper-discount-model/research.md)，程式在
`src/sweetspot/forecast/models/seasonal_record.py`。

### 預測什麼

和 `seasonal-freq` 相同：對每個折扣等級 d 與每場未來季節特賣 k，給出「分析時點之後、第 k 場結束以前，至少出現一次從 < d
進入 ≥ d 的折扣」的機率。差別在於它會對比過去更深的折扣給出機率。

### 規則

設 M 為本身已結束季節特賣的最深折扣（取到 5 的倍數），s 為「首次達到 M 之後又過了幾場」（上限 4）。

1. **資料太少**：本身已結束的季節特賣少於 `min_sales` 場時，和 `seasonal-freq` 完全相同：用整體比例，信心為低。
   `min_sales = 1` 時，只有本身沒有任何季節特賣紀錄的遊戲走這條路。
2. **見過的等級（d ≤ M）**：
   - 每場的機率 p_w(d) = 本身各場中最大折扣 ≥ d 的加權比例。第 i 場（由舊到新，共 n 場）的權重是 0.5^((n−1−i)/`half_life`)。
   - 累積機率 = 1 − (1 − p_w(d))^k × Π(1 − h(M, s + j))。意思是：沒有任何一場達到 d，而且也沒有任何一場創新低，
     因為創新低一定也達到了 d。
3. **比過去更深（d > M）**：累積機率 = 「k 場之後的最深折扣 ≥ d」的機率。
   - 每一場以 h(M, s) 的機率創新低：M 加深 J 級，s 歸 0。否則 s 加 1。
   - 每個分析時點對所有狀態只算一次倒推表，每款遊戲直接查表。
4. **創新低機率 h(M, s)**：
   - **樣本**：分析時點以前，參考資料集所有遊戲已結束的季節特賣中，之前已有 `min_sales` 場紀錄的每一場。
   - **分組**：依它之前的狀態分組。M 分 4 組：淺於 -50%、-50%～-70%、-75%～-85%、-90% 以上；s 也分 4 組：0、1、2–3、4 以上。
   - **加法平滑**：M 組比例 =（次數 + 20 × 全體比例）/（場數 + 20）；h =（格子次數 + 20 × M 組比例）/（格子場數 + 20）。
     全體沒有樣本時 h = 0，這時等於 `seasonal-freq`。
   - **區域**：`hazard_history = TW+US` 時，台灣區目標也加入美國區的季節特賣紀錄，只用折扣百分比，並在原因中標示。
     美國區目標只用美國區。
5. **加深幾級 J**：依 M 組，從創新低的樣本估計，上限 5 級。某組少於 20 次時，改用全體的分布。
6. **原因**依序說明：
   - 本身的紀錄
   - 過去最深折扣
   - 最近 4 場的方向與近期加權
   - 上一次創新低，以及查表的比例和樣本數

   從沒打折過的遊戲另有措辭，見 [004 model-api 契約](../../specs/004-deeper-discount-model/contracts/model-api.md)。

### 特徵分析（調參組，004 spec FR-004）

`uv run python scripts/feature_analysis.py` 的分析單位：每款遊戲、每場之前已有 2 場紀錄的季節特賣，看這一場是否創新低，
也就是比之前每一場都深。

- 台灣區 5,364 場，創新低 19.7%。
- 美國區（2016 年起）14,353 場，創新低 15.5%。
- `seasonal-freq` 對這些情況一律給 0。

| 特徵 | 分組 | 台灣區 | 美國區 |
|---|---|---|---|
| 過去最深 | 淺於 -50% / -50%～-70% / -75%～-85% / -90% 以上 | 37.3% / 19.3% / 6.7% / 4.2% | 36.5% / 17.8% / 5.2% / 1.4% |
| 距上次創新低 | 0 / 1 / 2 / 3 / 4 場以上 | 36.6% / 22.9% / 12.9% / 15.6% / 7.7% | 33.0% / 29.1% / 22.2% / 19.0% / 5.1% |
| 最近 4 場的趨勢 | 加深 / 持平 / 變淺 | 32.1% / 13.9% / 9.7% | 23.9% / 9.9% / 7.8% |

- 剛創新低的遊戲最容易再創新低；停在同一個低點越久，越不會再往下。方向和「該輪到了」的直覺相反。
- 趨勢的效果大多已經包含在「距上次創新低」裡。
- 創新低時加深多少（每級 5 個百分點）：過去最深淺於 -70% 的，多半加深 1–2 級；-75% 以上的，約 75% 只加深 1 級。

### 已知限制

1. **低機率區段的實際發生率較高**（feature 007 修正說明，`specs/007-non-seasonal-discounts/prototype/t033_censoring.py`）：
   上方校準表 0.0–0.1 那一格，實際比預測高約 3 個百分點。原因有兩個，而且大約各佔一半：
   - **002 評分的截斷規則**：「已發生」只要在資料截止前出現就計分，即使那場特賣還沒結束；「未發生」要等特賣結束才計分，否則截斷。
     越接近資料截止的分析時點，留下來的單位越偏向已發生，所以實際比例被高估。
   - **季節特賣以外的折扣**：模型只從季節特賣估計，評分卻計入任何時候的到價。

   | 現行（002 框架） | 568,219 | 0.019 | 0.050 |

   已結束的單位中，已發生的有 66% 是在季節特賣以外先到價。
   - 其他格子在「只計已結束」時，實際比預測**低** 2–6 個百分點（例如 0.4–0.5：0.448 → 0.426）。
     這個子集偏向較早的分析時點，不能直接推論整體高估，但現行校準表中段的「實際高於預測」也有一部分來自同一個截斷規則。
   - 模型之間的比較用同一套規則，所以判定仍然公平；框架本身不改（feature 007 使用者 2026-09-26 的決定）。
     非季節預測的評分只計資料涵蓋整個期間的單位，沒有這個問題（「評分框架設定」）。
2. **不分季節、不看遊戲年齡**：美國區的場數效果很強（第 2–4 場創新低 41–49%，12 場以上 5.7%），大部分已由 s 與 M 表達，但沒有直接使用場數。
3. **發售前的季節特賣**仍然計入本身的紀錄，同 `seasonal-freq` 已知限制 8。
4. **12 個月以後**：曲線仍然輸出 5 年（美國區回測要用），但決策規則 2.0.0 只看 12 個月；長期的機率準確度由美國區 1–5 年驗證。
5. **只有 1 場紀錄時，見過的等級直接照那一場**：例如只有 1 場 -50%，「下一場 ≥ -50%」就是 100%。依場數分組的分數證明整體可以接受
   （台灣區 0.0710），但個別遊戲可能過度自信。

## `seasonal-freq` v1.0.0（基準模型）

2026-09-25 到 2026-09-26 的現行模型，保留作為所有模型比較的下限（憲章 IV）。以下是它當時的定義與回測，不再更新。

### 預測什麼

對每個折扣等級 d（-5% 到 -95%，每 5 個百分點）和分析時點之後的每一場季節特賣 k，
給出「分析時點之後、第 k 場季節特賣結束以前，至少出現一次從 < d 進入 ≥ d 的折扣」的機率。
分析時點當下已經在進行的折扣不算，那是現價，由 feature 003 判斷。

### 規則

1. **本身的特賣紀錄**：這款遊戲在分析時點以前**已結束**的季節特賣中，每場的最大折扣。
   - 價格序列必須在特賣開始前就開始，而且特賣結束時仍在資料已知範圍內，才計入。
     沒有資料的特賣不計，不當作 0%。
   - `history` = `TW`：只用台灣區。`TW+US`：台灣區沒有資料的特賣，補用美國區的折扣百分比。
   - 預測美國區時一律只用美國區。
2. **每場的機率** p(d) = 本身特賣紀錄中，最大折扣 ≥ d 的比例。
3. **資料太少**：本身的特賣紀錄少於 `min_sales` 場時，p(d) 改用整體比例：
   分析時點以前，資料集內所有付費遊戲已結束的季節特賣中，最大折扣 ≥ d 的比例，每場特賣同權重。
   這時信心等級是 `low`。
4. **累積機率**：第 k 場季節特賣 = 1 − (1 − p(d))^k。各場特賣視為獨立，春夏秋冬視為同類。

### 已知限制

1. **比過去更深的折扣一律給 0**：只要本身有 ≥ 2 場紀錄，就不會預測更深的折扣。
   遊戲變老、折扣加深是常態，所以長期（1–5 年）預測比整體比例還差（0.1791 vs 0.1087）。
   **feature 003 預估長期最低價時必須標示這一點**，這也是 feature 004 最明確的改進方向。
2. **不分季節**：春夏秋冬視為同類。
3. **各場特賣視為獨立**：沒有考慮「上一場剛打過深折扣，下一場通常較淺」這類關聯。
4. **季節特賣以外的折扣**（發行商促銷、主題節慶）不預測，但會計入「在下一場季節特賣前已出現」，所以會拉低分數。
5. **美國區 2015 夏特以前的季節特賣有每日特價與限時搶購**，同一場特賣中價格會變動。
   「特賣期間最大折扣」涵蓋了這種情況，但早期特賣的最大折扣可能偏深。
6. **資料庫中沒有任何已結束的季節特賣時無法估計**：整體比例沒有樣本，結果是 `model-error`，
   並附原因「資料庫中沒有任何已結束的季節特賣，無法估計」。實際資料不會發生，回測排程也避開了這種時點。
7. **不預測原價變動**：台幣價格 = 分析時點的原價 × (1 − 折扣)，換算由 feature 003 負責。
8. **發售前的季節特賣被計入本身的特賣紀錄**（feature 003 發現）：價格序列在發售前就開始（例如預購）時，
   發售前的季節特賣也算一場。台灣區 305 場（1.9%，137 款）、美國區 1,354 場（3.7%，366 款）。
   其中台灣區 212 場有折扣，可能是預購折扣，或 Steam 的發售日其實是重新上架或重製版的日期，
   所以不能直接以發售日排除。feature 004 的候選。

## `non-seasonal` v1.0.0（非季節促銷預測）

feature 007。設計見 [007 research R1](../../specs/007-non-seasonal-discounts/research.md)，程式在
`src/sweetspot/forecast/nonseasonal/`。和季節模型分開：輸出以「未來 h 天」為單位，決策規則不讀它，只在報告顯示。

### 預測什麼

對每款遊戲、每個期間 h（30／60／90 天）與每個折扣等級 d（5%–95%），給出「分析時點之後 h 天內，至少出現一次 d 的**非季節到價**」的機率。

- **非季節到價**：價格從 < d 進入 ≥ d 的那一刻，不在任何季節特賣的期間內（開始前 1 天起算，`TOL`）。追蹤起點不算。
  分析時點已經 ≥ d 的折扣不是新的到價。
- **非季節促銷**（只用於報告的依據）：從無折扣到回到無折扣的一段，和任何季節特賣都沒有重疊。
- 主題節不另外分類：2025 年起 37 個主題節涵蓋 38% 的天數。

### 規則

1. **本身比例** f(h, d)：看得到的歷史中最近 365 天，起點 t 連續分布時，(t, t + h] 內出現 d 到價的比例，以區間聯集精確計算。
   `history = TW+US` 時，台灣區開始追蹤以前用美國區同一商品的折扣日期補足。
2. **整體比例** b(h, d)：參考資料集所有付費遊戲的 f(h, d) 平均（只看台灣區、歷史至少 h + 30 天的遊戲）。它也是回測的參照分數。
3. **平滑**：p1 = (w·f + k·b) / (w + k)。w = 本身歷史的月數 − h / 30.44，k = `smoothing`（月）。
   本身歷史不足 h + 30 天時，p1 = b。
4. **時鐘**（`clock = true`）：
   - 樣本：參考資料集每款遊戲每 14 天取一個時點 t。
   - 狀態：過去 365 天的促銷次數組（0／1–2／3–4／5 次以上）、距上一次開始是間隔中位數的幾倍（< 0.5／0.5–1／1–1.5／≥ 1.5；不足 3 次另成一組）、t 時是否正在折扣、(t, t + h] 內是否有季節特賣。
   - 樣本的特徵只用 t 以前的資料，結果只用 (t, t + h]；分析時點只使用 t + h 早於分析時點 1 天以上的樣本。
   - 比例依「次數組」→「次數組 × 折扣 × 季節特賣」→「完整狀態」逐層平滑（強度 20）。
   - 係數 = 完整狀態的比例 ÷ 次數組的比例。p = p1 × 係數。
   - 這裡的「促銷」是從無折扣開始的非季節到價；「期間內是否有季節特賣」用分析時點已知或估計的特賣。
5. **輸出**：p = min(p, 0.99)。先讓 d 越深機率不增加，再讓 h 越長機率不減少。
   後一步在早期的分析時點很重要：台灣區歷史還不夠長時，60／90 天的整體比例是 0（research、validation T018）。
6. **依據**：看得到的期間與來源、過去一年的非季節促銷次數、間隔中位數、最常見的深度、上一次開始的日期與深度、距今天數、是否正在促銷。

### 已知限制

1. **低到中段低估 1–6 個百分點，最高一格高估約 3 個百分點**（上表）。報告附上的是「可能更早到價」實測的命中率，不受這個偏差影響。
2. **台灣區歷史只有約 21 個月**：較早的分析時點主要靠美國區補足與整體比例；60／90 天在 2025 年初幾乎沒有整體比例可用。
3. **深度只從過去的比例估計**：一款遊戲第一次出現更深的非季節促銷，機率只能來自整體比例與平滑。
4. **樣本不獨立**：同一段促銷會出現在許多重疊的窗口與取樣時點中；區間依遊戲成對重抽樣，已經考慮同一款遊戲的相關性。
5. **決策不使用**：見決策規則已知限制 4。

### 規則

1. **曲線範圍**：只用結束時間在分析時點 12 個月內的季節特賣，一般信心與低信心相同。v1.0.0 的一般信心用全部時點。
2. **12 個月內最低折扣 P_min**：範圍內最後一個時點，累積機率 ≥ 50% 的最深折扣等級。
3. **P_min 為 0 的一般信心遊戲**（過去季節特賣都沒打折）：改用「沒有本身歷史時的預測」、範圍 12 個月，決策為低信心。
4. **容許差距** = min(max(原價 × g, 下限), 上限)；P_min 淺於分界時 g 用 `gap_pp_shallow`，否則用 `gap_pp_deep`。
5. **目標價** = P_min 的價格 + 容許差距；**甜蜜價** = 價格不超過目標價的最淺折扣等級的價格。
6. **甜蜜時點**：範圍內，「≥ 甜蜜價折扣」的累積機率第一次 ≥ 50% 的季節特賣。
7. **等待對照表**：從下一場到甜蜜時點，每場「累積機率 ≥ 50% 的最深折扣」與價格。
8. **分組**（依序）：
   1. 無法預測：預測不是 ok，或決策出錯
   2. 現在買：現價 ≤ 甜蜜價
   3. 低信心：信心為低、P_min 為 0 改走低信心、原價與價格歷史不一致，或價格歷史停止更新（v2.1.0）
   4. 即將到價：甜蜜時點在前 `soon_sales` 場
   5. 繼續等：其餘
9. **台幣換算**：原價取現價那一筆觀測（Steam 現價快照優先）的原價，沒有時用價格歷史在分析時點的原價。
   金額以分計算、比較一律乘開成整數，顯示時以元四捨五入。

### 已知限制

1. **購買選項**：價格與價格歷史預設是願望清單 App 在台灣區的預設購買選項（feature 006 起跟著它對應的 ITAD 商品）。
   feature 009 起，報告列出同一遊戲的其他版本（本體加上它自己的 DLC 的套件或組合包；2026-09-27 為 26 款、33 個，可指定 25 款、32 個），
   使用者指定後那款遊戲改用指定版本的歷史（見「使用者指定的版本」）。**含其他遊戲的組合包**（34 款、130 個）仍然不能指定；
   其中同時含 2 款以上願望清單遊戲的（2026-09-27 為 6 個），由 `bundle-advice`（feature 010）在報告的「組合包」一節比較與建議，決策不使用。
2. **12 個月內最低價可能更低**：規則回測中，判為「現在買」的案例仍有 44.4% 在之後 12 個月內出現更深的折扣
   （`seasonal-record` v1.0.0 是 43.2%，`seasonal-freq` ＋ v1.0.0 是 48.6%）。這句提示由現行模型提供（`deeper_caveat`），數字來自下方的規則回測。
3. **低信心的甜蜜時點**：`seasonal-record` v1.1.0 改用新遊戲前幾場的實際比例後，規則回測中 57.9% 在甜蜜時點前到價
   （v1.0.0 用全體比例時只有 5.9%）。低信心只剩兩種遊戲：本身沒有任何季節特賣紀錄的（多半是新遊戲），以及曲線上沒有任何折扣達到 50% 的；
   決策數 1,748 次（v1.0.0 為 2,028 次）。正在打折的新遊戲，現價常常已經不高於新依據的甜蜜價，所以規則會判為現在買（「現在買」優先於「低信心」）。
4. **季節特賣以外的折扣**：報告顯示非季節預測（`non-seasonal`，feature 007），但**決策不使用**：甜蜜價、甜蜜時點與分組只看季節特賣。
   決策也會在原因中列出比季節特賣紀錄更深的非季節折扣。
   - 照建議買的人本來就會在非季節促銷到價時買：調參組中「即將到價」有 61% 是在非季節促銷買到，中位數比甜蜜時點早 38 天。
   - 讓規則使用非季節促銷的上限很小（feature 007 research R0.3，調參組）：
     甜蜜價參考過去一年的非季節紀錄，只改變 6.7% 的決策，多省 NT$8、多等 16 天，c = 20 時淨效益差 −2.4 [−7.7, +2.5]，不顯著；
     事後最低價的上限多省 NT$36。之後若要改規則，應該從時鐘預測出發。
5. **「繼續等」的到價率較低**：61.9%（`seasonal-record` v1.0.0 是 62.5%，`seasonal-freq` ＋ v1.0.0 是 87.5%）。
   - 新的「繼續等」多半落在創新低機率剛過 50% 的時點，這種時點本來就只有大約一半會到價。
   - 到價率不是校準指標；換版時看的是「照建議買」多省多少、多等多久（004 spec FR-021）。

## 決策規則 `sweet-price` v3.0.0（候選，**未採用**）

feature 005「等待成本」。設計與原型見 [005 research](../../specs/005-waiting-cost/research.md)，程式在
`src/sweetspot/decision/rule.py`（`RULES["3.0.0"]`）。驗證組未通過換版的硬門檻，使用者 2026-09-26 決定不換版，
現行規則仍是 2.0.0。3.0.0 保留在程式中，可以用 `report --rule 3.0.0` 預覽、用 `backtest-rule --rule 3.0.0` 回測。

### 規則

用「每多等一個月要多省 NT$c」取代 2.0.0 的容許差距，12 個月範圍不變。

1. **路徑**同 2.0.0：
   - 低信心用整體比例。
   - 一般信心、但 12 個月內沒有任何折扣達到 50% 時，改用「沒有本身歷史」的曲線，決策為低信心。
   - 原價不一致時，決策為低信心。
2. **基準價** B = 現價；現價未知時用原價，而且不能判為現在買。
3. **選項**（目標 d，最晚等到範圍內第 K 場），設 F_i 為第 i 場結束以前達到 ≥ d 的累積機率：
   - 期望實付 = Σ(F_i − F_{i−1}) × price(d) ＋ (1 − F_K) × 原價，也就是**到期沒達到時，在第 K 場結束時以原價買**。
   - 期望等待（月）= Σ(F_i − F_{i−1}) × 第 i 場開始 ＋ (1 − F_K) × 第 K 場結束。一個月 = 365 / 12 天。
   - 淨效益 = (B − 期望實付) − c × 期望等待。金額先四捨五入成整數分再比較。
4. **選擇**：每一場取淨效益最高的目標，相同時取較淺的；所有場中取最高而且 > 0 的，相同時取較早的一場；
   沒有任何選項 > 0 時現在買。
5. **甜蜜時點** = 最晚那一場以前，累積機率第一次 ≥ 50% 的那一場；沒有的話是最晚那一場。另外輸出「最晚等到」。
6. **分組**同 2.0.0；12 個月內最低價只當參考。

### 參數與依據

| 參數 | 值 | 性質 | 依據 |
|---|---|---|---|
| `wait_cost_twd`（c） | NT$20／月 | **使用者偏好** | plan 原型只用調參組與願望清單試算 0–120，使用者選 20（005 research R0.1、R0.6）；硬門檻用這個程式預設值，不用設定檔當下的值 |
| `miss_price` | 原價 | 規則常數 | research R2：「現價」與「原價」在回測中幾乎相同，但「現價」高估正在打折的遊戲等下去的價值；「沒達到時的最深較淺折扣」太樂觀而排除 |
| 甜蜜時點的門檻 | 50% | 規則常數 | 同 2.0.0 的 `timing_threshold`；research R3 |
| 範圍 | 12 個月 | 規則常數 | 同 2.0.0 |

### 原型與正式實作（調參組）

- 正式實作和原型逐案對照：22,683 次決策中 99.67% 完全相同，其餘 75 次的淨效益差距都在 1 分以內（平手規則，research R0.7）。
- 真實願望清單上，c 從 0 提高到 120，65 款遊戲沒有一款的期望等待變長（`scripts/wait_cost_monotonic.py`）。
- 3.0.0 比最簡單的「下一場以最可能的折扣買」多省而且等得更少，每個 c 都顯著較好（research R0.1）。
- 期望多省大致準確（預測 NT$308，實際 NT$296），但到期前達到的機率偏樂觀：預測 96.6%，以實際特賣結束日計分實際 89.8%（一般信心本身曲線 97.0% → 91.8%，低信心或沒有本身歷史 81.9% → 9.3%；feature 008 research R9）。

### 判定（2026-09-26，比較文件「規則驗證組比較（sweet-price 3.0.0）第 1 次」）

每月重新評估，3.0.0 減 2.0.0 的平均淨效益差距（依遊戲成對重抽樣 2,000 次的 95% 區間）：

| c | 調參組（1,270 款） | 驗證組（1,313 款） |
|---|---|---|
| 0 | −2.4 [−3.2, −1.6] | −2.5 [−3.7, −1.5] |
| 10 | +0.0 [−1.2, +1.2] | −1.2 [−2.8, +0.3] |
| **20** | +4.0 [+2.2, +5.8] | **+1.7 [−0.7, +4.2]**：區間含 0，**未通過** |
| 30 | +8.5 [+5.8, +11.3] | +5.7 [+2.6, +8.6] |
| 50 | +20.5 [+16.5, +24.7] | +18.5 [+14.4, +22.6] |

- 驗證組 c = 20：3.0.0 平均多省 NT$201、多等 18 天；2.0.0 為 NT$214、41 天。
- 固定決策（004 的做法）時 c = 20 的差距是 +11.2 [+8.4, +14.0]，但判定依使用者的決定，用每月重新評估。
- 3.0.0 **沒有找到更多可省的錢**，它依 c 在多省與多等之間取捨；2.0.0 大約落在 c ≈ 10 的位置。
- 判為現在買之後 12 個月內又更便宜的比例，從 44.2% 升到 60.3%（驗證組，c = 20），因為 3.0.0 更常建議現在買。

### 已知限制（若之後重新考慮）

1. **到期前達到的機率偏樂觀**約 7 個百分點（預測 96.6%，實際 89.8%），主要來自低信心的曲線（81.9% → 9.3%）；一般信心的本身曲線約 5 個百分點。feature 008 的試算中，任何校準（後處理或改模型結構）都沒有改善 3.1.0 的淨效益（調參組 +4.0 → +2.7～+4.2），所以它不是第 2 次嘗試的方向。
2. **只預測季節特賣**：實際常在非季節折扣就到價，所以實際等待比預測短。
3. **風險中性**：「50% 機率多省 NT$200」和「確定多省 NT$100」視為相同。
4. **12 個月以後**：範圍放寬到 24 個月時，c = 20 有約 20% 的決策、願望清單 23 款會把最晚期限延到 12 個月以後，期望只多等約 4 個月（只計數，未評估結果）。

## 價格歷史：跟著 Steam 預設購買選項（feature 006）

這一節定義「一款遊戲的價格歷史是哪一份」。它是資料定義，不是模型或規則；改變它不改變模型版本。
依據見 [006 research](../../specs/006-version-tracking/research.md) R1–R4。

1. **預設購買選項**：每日更新時，App 在台灣區的購買選項中，原價與售價都和 `price_overview`（報告的現價）相同的那個套件；
   剛好一個才算，組合包不算。0 個或 2 個以上是「無法唯一決定」。
2. **版本**：預設購買選項在 ITAD 對應的商品。每天每款記錄一筆版本紀錄（只新增）。相鄰兩筆的 ITAD 商品不同就是**版本更換**；
   第一筆和 App 本身的 001 對應比較。只換套件、ITAD 商品不變，不算版本更換。
3. **驗證**：和 App 本身的商品相同時沿用 001 的驗證；不同時，ITAD 商品的每個別名都必須是這個 App、或本體加它自己的 DLC 的套件；
   販售中的套件必須和預設選項同價（價格取自 App 自己的購買選項）；含組合包或其他遊戲就拒絕。沿用的驗證保留原始驗證時間。
4. **使用哪一份歷史**：分析時點以前最新的版本紀錄。
   - 已驗證：只用這個 ITAD 商品的台灣區與美國區歷史，不和舊版本接在一起。
   - 驗證失敗：無法預測，原因寫出拒絕理由。
   - 無法唯一決定、ITAD 沒有這個購買選項、沒有紀錄：用 App 本身的商品。
5. **停止追蹤**：最新版本紀錄顯示 ITAD 對這個商品沒有 Steam 現價，而 Steam 仍在販售時，「已知至」截在最後確認時間
   （這個商品的最新觀測，與最後一次仍有 Steam 現價的版本紀錄，取較晚者）。之後的特賣視為未知；規則 v2.1.0 把決策降為低信心。
6. **回測資料集**：同樣依截止時間的版本紀錄選商品。版本紀錄從 2026-09-26 起才有，所以 2026-09-25 截止的資料集不受影響。

**已知限制**：

- 版本紀錄只記錄「偵測到」的時間。Dying Light 在 2025-01 就換了版本，2026-09-26 才偵測到；它的新版本歷史從 ITAD 開始追蹤的
  2025-06-26 起算，中間約 5 個月未知。之後以更晚的截止時間建立資料集時，它更早的分析時點看不到歷史。
- 001 的驗證用套件本身的「最佳購買選項」當價格，可能被組合包誤導；本 feature 只在新的版本驗證中修正，參考遊戲的驗證不變。
- 整體比例（`seasonal-record` 的創新低機率）用全部遊戲的歷史，換版本的遊戲也在其中；換版本會讓其他遊戲的整體比例數字微幅改變
  （006 validation：51 款原因中的場數、1 款甜蜜價）。

## 使用者指定的版本（feature 009）

這一節定義使用者指定版本時「一款遊戲的價格歷史是哪一份」。它是資料定義與使用者偏好，不是模型或規則；模型
（`seasonal-record` v1.1.0、`non-seasonal` v1.0.0）與規則（`sweet-price` v2.1.0）都不變，所以不做驗證組比較。
依據見 [009 research](../../specs/009-purchase-options/research.md) R1–R8。

1. **購買選項紀錄**：每日更新在版本步驟之後記錄每款遊戲的所有購買選項（套件與組合包、台灣區現價與原價），每天每個選項一列（只新增）。
2. **版本**：內容是這個 App 加上零或多個它自己的 DLC 的購買選項。版本才查 ITAD 商品並驗證（006 的規則，以這個選項自己的價格為準；
   別名中等於這個組合包本身的 `bundle/N` 可以接受，其他組合包別名仍拒絕）。含其他遊戲、不含本體或內容查不到的，不是版本。
3. **版本的價格歷史**：存在 `app_id` = 願望清單 App、`external_id` = 版本的 ITAD 商品、來源 `itad-option-history` 之下。
   台灣區每天抓；美國區只抓使用者指定的版本。預設序列、季節特賣偵測、區域一致性與回測資料集都不讀這個來源。
4. **指定**：`sweetspot.toml` 的 `[purchase_options]`（`App 編號 = "sub/N"` 或 `"bundle/N"`）。產生預測時依**目前的設定**與分析時點以前
   最新一次購買選項紀錄解析；指定的選項不在購買選項中、不是版本、ITAD 沒有對應、驗證未通過、或那個時點還沒有紀錄時，退回 Steam 預設版本並寫出原因。
   指定的剛好是 Steam 預設時固定那個選項，之後 Steam 換預設也不跟著換。
5. **只影響那款遊戲**：季節與非季節預測的整體比例、所有回測都只用預設版本的歷史；指定版本的歷史只用來產生那款遊戲自己的證據。
   現價取購買選項紀錄中這個選項的價格與版本歷史最新一筆中較新者。版本歷史不足時照現行規則判低信心（不借用預設版本的折扣）；
   ITAD 停止追蹤時照 006 截短「已知至」並判低信心。

**已知限制**：

- 其他版本和標準版的折扣常常不同（2026-09-27 清點：預設版本 305 場台灣區折扣中，其他版本同折扣 70%、較淺 17%），
  但指定版本自己的歷史不一定和標準版一樣長；新上架的版本（例如 Granblue Fantasy: Relink 無盡黃昏）沒有特賣紀錄時是低信心。
- 低信心的新遊戲依據（v1.1.0 規則 1）用的是 App 本身的發行日，不是版本上架的日期；原因中的「發行於」指遊戲本體。
- 美國區歷史只在指定生效後的每日更新才抓；剛改設定、還沒更新前的報告只用台灣區的紀錄，原因寫明。
- 組合包的價格以 Steam 對未擁有任何內容的顯示價格為準；已擁有部分內容時的折抵價不在範圍內。

## 組合包建議 `bundle-advice` v1.0.0（feature 010）

同時含 2 款以上願望清單遊戲的組合包，什麼時候買比各自分開買划算。**它不是預測模型**：不預測組合包自己的價格，
而是用 Steam 的定價方式和各款既有的預測推算；結果只在報告的「組合包」一節顯示，各款遊戲的決策（`sweet-price` v2.1.0）不讀它。
依據見 [010 research](../../specs/010-wishlist-bundles/research.md) R0–R4，程式在 `src/sweetspot/decision/bundles.py`。

### 預測什麼

- **組合包價** = (1 − 組合包折扣) × 各內容當下 Steam 價格的加總。組合包折扣是 Steam 購買選項的 `bundle_discount_pct`，每天記錄。
  清點（2026-09-27）：台灣區 6 個組合包在 ITAD 歷史上 99.9–100% 的天數成立；過去 8 個「組合包 × 季節特賣」中，組合包都剛好比全部分開買便宜組合包折扣的比例。
- **單場機率**：一款遊戲在**一場**季節特賣中達到 d 的機率，取 `seasonal-record` 對下一場的機率（預測的第一個時點；research R0.1 的 M1）。
  所以未來每一場的推算都相同，報告只寫一行「任何一場季節特賣（最早〈下一場〉）」。
- **同時到價機率**：各款單場機率之積（獨立假設）。

### 規則

1. **對象**：分析時點以前最新一次購買選項紀錄中，內容含 ≥ 2 款在願望清單中的遊戲的組合包。內容全部是願望清單遊戲或它們的 DLC 的是**純粹**組合包，其餘是**混合**。
   混合組合包只比較（多付的金額、多得的內容），不推算、不建議。
2. **分開買的計畫**（spec 的「各自在甜蜜時點分開買」）：各款的甜蜜價加總，「現在買」的遊戲用現價；最晚時點 = 各款甜蜜時點中最晚的一場，全部「現在買」時為現在。
3. **下一場季節特賣的推算**：在各款單場機率之積 ≥ 50% 的折扣組合中，取 Σ 原價 × (100 − d) / 100 最小的一組（d = 0 表示不打折，機率 1；相同時取機率較高者）。
   推算價 = (1 − 組合包折扣) × 那組價格加總，以分計算、四捨五入；同時到價機率 = 那組的機率之積。
4. **建議**（依序）：
   1. 組合包現價 ≤ 分開買的計畫 → 現在買組合包。
   2. 最晚時點不是現在、同時到價 ≥ 50%、推算價 ≤ 分開買的計畫 → 在下一場季節特賣買組合包（不會比最晚的甜蜜時點更晚）。
   3. 其他 → 各自在甜蜜時點分開買；同一場特賣兩款都買時，組合包仍便宜組合包折扣的比例。
5. **不給建議**（只給比較並寫出原因）：有內容沒有 ok 的預測或決策、有一款使用者指定了其他版本、當天公式檢查不一致或無法檢查、有一款現價過舊（24 小時）、12 個月內沒有季節特賣。
6. **信心**：任一款的預測是低信心或決策是「低信心」時，建議標示為低信心（照常產生）。
7. **公式檢查**：|Steam 組合包現價 − (1 − 組合包折扣) × Σ 內容現價| ≤ max(NT$2, 1%) 為一致。願望清單遊戲用決策的現價，其他內容用同一次更新記錄的現價。

- 隨機配對 1,902 對（3 個固定種子的隨機排列），同發行商配對 778 對（第一發行商相同，每家最多 20 對）。
- 同發行商的遊戲確實一起打折（殘差共變異 0.033，隨機 0.005），但方向是更容易同時到價，所以獨立假設對它們偏保守，不另外修正。
- 原型：`specs/010-wishlist-bundles/prototype/p1_pairs.py`、`p2_cheapest.py`（約 20 秒）。

### 已知限制

- **補完組合**：已擁有組合包的部分內容時，Steam 的價格會更低；報告只知道全部未擁有時的價格（不讀使用者的遊戲庫）。
- **組合包折扣假設不變**：推算用分析當天的組合包折扣；清點期間台灣區沒有改變過，但 Steam 可以改。
- **只算季節特賣**：季節特賣以外的促銷不推算組合包（`non-seasonal` 不合併）。
- **同一時刻**：同時到價是「兩款在同一場特賣中都達到」；兩款的最深折扣可能不在同一時刻（例如限時特價），買組合包的那一刻不一定兩款都在最低。
- **0.9 以上略偏樂觀**：同時到價 0.9 以上一組預測 0.939、實際 0.905。
- **命中率來自虛構配對**：實際的組合包通常是發行商搭配的遊戲，更接近同發行商配對；引用隨機配對的數字較保守。

## 評分框架設定

以下是**框架設定，不是模型參數**。它們決定「怎麼評分」，所以不為了讓某個模型分數變好而調整。
修改其中任何一項，都會改變資料集識別碼或比較方法，必須在這一節記錄理由與日期。

| 設定 | 值 | 理由 |
|---|---|---|
| 折扣等級 | 5%–95%，每 5 個百分點 | 涵蓋所有實際出現的折扣；Steam 折扣大多是 5 的倍數 |
| 輸出範圍 | 分析時點後 60 個月內的季節特賣 | 超過 5 年無法以現有資料回測 |
| 季節是否在舉辦 | 分析時點前 18 個月內舉辦過 | 涵蓋同一季節最長的間隔；季節停辦時自動停止預估 |
| 評估窗口 | 台灣區：預估結束在 (as_of, +12 個月]；美國區：(+12, +60 個月] | 台灣區資料只有約 21 個月；長期由美國區折扣百分比驗證 |
| 分析時點 | 每月 1 日（UTC），從資料中第一場已結束的季節特賣之後開始 | 在沒有任何歷史的時點預測沒有意義 |
| 點預測門檻 | 累積機率首次 ≥ 0.5 | 命中率與時間誤差用；不影響 Brier |
| 校準分組 | 每 0.1 一組 | 慣例 |
| 比較的重抽樣 | 依遊戲成對抽樣 2,000 次，種子由資料集識別碼決定 | 同一遊戲的評分單位彼此相關；固定種子才能重現 |
| 加權 | 每款遊戲同權重 | spec clarify 的決定 |
| 調參組與驗證組 | SHA-256(`steamsage-004-split:<app_id>`) 前 8 個十六進位字元，偶數為調參組、奇數為驗證組；鹽固定不改 | 004 spec FR-009：參數只在調參組選，換版只看驗證組；整體比例仍用全部遊戲 |
| 驗證組比較次數 | 最多 3 次，每次都記錄 | 004 spec FR-013 |
| 「比本身過去更深」分組 | 本身至少 1 場已結束的季節特賣，而且 d 深於其中的最深折扣 | 004 spec FR-014；只報告，不影響判定 |
| 照建議買：每月重新評估 | 每個分析時點改照當時的決策；兩個分析時點之間價格進入當時的甜蜜價就買；12 個月內沒買就以 12 個月時的價格買 | 005 spec FR-011：最接近每天更新報告的實際用法，規則換版以它判定 |
| 淨效益 | 多省（元）− c × 多等天數 ÷ (365/12)；評估成本 0、10、20、30、50、80 加上規則本身的 c | 005 spec FR-010、FR-012 |
| 規則比較的區間 | 兩邊都可評估的決策；每次決策的平均差距，依遊戲成對重抽樣 2,000 次，種子由資料集識別碼決定 | 005 spec FR-013 |
| 規則驗證組比較次數 | 每個候選規則版本最多 3 次，和模型比較分開計算；比較之後改 c 也算一次 | 005 spec FR-014 |
| 非季節的期間 | 30／60／90 天 | 報告能用、回測能驗證的範圍；不為分數調整（feature 007，2026-09-26） |
| 非季節的計分條件 | 只計「已知至 ≥ 分析時點 + h」的單位，已發生的也一樣 | 避免 002 的截斷偏差：已發生與未發生用同一個條件（feature 007 spec FR-007） |
| 非季節的季節特賣容許 `TOL` | 開始前 1 天起算 | ITAD 的時間和 Steam 的開始時間不完全一致（007 research R0.4：調參組 204 次變化落在開始前 1 天內） |
| 非季節資料集識別碼 | 季節資料集識別碼加上期間、`TOL` 與計分條件 | 兩份非季節結果只在識別碼相同時比較 |
| 非季節驗證組比較次數 | 每個模型版本最多 3 次，和模型、規則比較分開計算 | 007 spec FR-009 |
| 只計已結束的校準（`finished_calibration`） | 只計實際特賣在資料內已結束的單位；Brier 每款遊戲同權重，各組的預測與實際是逐單位平均；依信心、本身場數、見過／更深、和過去最深的距離分組 | 只報告，不影響判定。002 的截斷規則讓中段的偏差方向顛倒（feature 008 research R0.3），這個指標讓已發生與未發生用同一個條件（2026-09-26） |
| 場數組的額外判準（`compare --target-groups`） | 除了 002 FR-029，另外要求指定的本身場數組（依分析時點本身已結束的季節特賣場數）台灣區 Brier 點估計都較低；feature 008 用 `0,1` | 改善集中在少數遊戲時，確保換上的版本真的改善了目標族群；只比 FR-029 更嚴（feature 008 spec FR-009，使用者 2026-09-26） |
| 模型比較次數 | 每個模型的每個版本各自最多 3 次（例如 `seasonal-record` 1.1.0 從第 1 次開始） | feature 008 spec FR-010 |
| 發行日 | 靜態的遊戲事實，模型可以讀；不在資料集識別碼中，回測結果以 `release_facts`（筆數與雜湊）記錄 | 發行日是過去的固定事實；納入識別碼會讓舊比較全部失效（feature 008 research R3，2026-09-26） |
