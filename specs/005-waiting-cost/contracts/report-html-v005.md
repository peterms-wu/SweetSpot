> （spec FR-015：c = 20、每月重新評估，平均淨效益差距 +1.7 [−0.7, +4.2]，區間含 0），使用者決定不換版

延伸 [003 的報告契約](../../003-sweet-price-report/contracts/report-html.md)。報告仍然只讀決策輸出的 dict，不做任何計算（憲章 VII）。
同一份報告程式同時支援 `/1`、`/2` 與規則 2.0.0、3.0.0；依決策輸出中的 `rule.version` 與欄位決定怎麼顯示。

## 規則 3.0.0 的顯示

1. **頁首偏好**：「等待成本 NT$20／月（使用者偏好）：每多等一個月要多省 NT$20 才值得；即將到價 = 下一場季節特賣」。
   不顯示容許差距。
2. **比較基準**：`version_changes` 照舊逐行列出，例如「等待成本從 NT$20 改成 NT$30」，並附「部分變動可能來自這個改變」。
3. **規則回測**：
   - `rule_backtest` 為 null 時，不顯示到價率，改顯示 `notes` 中的說明（research R8）。
   - 否則，各組標題顯示到價率，並註明「以等待成本 NT$20 回測」。
4. **摘要列**：
   - 名稱
   - 現價
   - 甜蜜價與折扣（目標）
   - 甜蜜時點與機率（最可能到價）
   - 最晚等到
   - 期望多省
   - 淨效益
   - 標籤
   - 變動

   現在買的遊戲，「期望多省」與「淨效益」顯示「—」，甜蜜價欄位顯示「等下去最好的選項」的值。
5. **展開後**：
   - 原因條列。
   - **等待對照表**：每列是 `wait_options` 的一列。
     - 欄位：最晚等到、目標價（折扣）、到期前達到、最可能到價（機率）、期望多省、期望等待（月，一位小數）、等待成本、淨效益。
     - 選中的那一列加粗並標示「建議」。
     - 第一列是「現在買」。
   - 12 個月內最低價（參考）。
   - 現價的來源與確認時間。

## 規則 2.0.0 的顯示

和 004 完全相同，包括 `ladder` 表格、容許差距與「12 個月內最低價」欄位。

## 保證（測試驗證）

1. 3.0.0 報告中每個台幣金額、機率與月數都等於契約中的值，逐一比對（spec SC-005）。
2. 3.0.0 報告不出現「容許差距」字樣；頁首一定出現 c 的值與「使用者偏好」。
3. 等待對照表的列數 = `wait_options` 的列數，恰好一列標示「建議」。
4. 003 報告契約的保證 1、3、4、5 不變：每款一列、跳脫、沒有外部資源、可重現。
