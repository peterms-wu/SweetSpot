## 範圍說明

專案的核心問題是「多省的錢」和「多等的時間」之間的取捨。現行規則 `sweet-price` 2.0.0 沒有直接衡量等待，而是用兩個間接的設定：

| 設定 | 作用 | 問題 |
|---|---|---|
| 12 個月範圍（規則常數） | 最多等 12 個月 | 等 1 個月和等 11 個月，只要省到一樣的錢，規則一律看成同樣好 |
| 容許差距（10/5 個百分點，下限 NT$30、上限 NT$100，使用者偏好） | 價格接近 12 個月內最低價就算到價 | 它比的是「和最低價差多少」，不是「多等的時間換到多少錢」 |

2026-09-26 的真實報告中（金額是各場「有 50% 機率達到」的價格，只是約略值）：

- NEKOPARA After（原價 NT$188）被建議從 2026 秋特多等到 2026 冬特，約多省 NT$9。
- 真・三國無雙 起源（原價 NT$1,990）被建議等到 2027 夏特，約多省 NT$298。

直覺上前者不值得多等、後者可能值得，現行規則分不出這兩種情況。另外，現行規則只看「有 50% 機率達到」的價格，
不理會「40% 機率多省 NT$300」這類低機率、高金額的情況。模型已經輸出完整的機率曲線，這些資訊目前沒有用上。

- **包含**：
  - 新的使用者偏好「等待成本」：每多等一個月，要多省 NT$c 才值得。
  - 新的決策規則 `sweet-price` 3.0.0：以模型的機率曲線計算每個選項的期望多省，扣掉等待成本後選淨效益最高的選項。
  - 規則回測的「照建議買」加上淨效益，並列比較 2.0.0 與 3.0.0。
  - 決策原因、決策輸出與報告呈現期望多省、等待成本與機率。
  - 使用者決定換版後，更新現行規則、規則回測數字與模型定義。
- **不包含**（之後的 feature）：
  - 預測模型本身的改變。模型維持 `seasonal-record` 1.0.0，曲線與參數不變。
  - 12 個月以上的決策範圍。本 feature 只報告「如果放寬範圍，會有多少決策選擇等更久」，作為之後放寬的依據（FR-017）。
  - 每款遊戲各自的等待成本（例如特別想玩的遊戲）。
  - 季節特賣以外的折扣、發售前特賣、版本追蹤。
- **不變**：
  - 預測輸出契約 `steamsage.forecast/1`。
  - 決策分組（現在買、即將到價、繼續等、低信心、無法預測）與低信心的判定。
  - 決策輸出的既有欄位名稱。契約升為 `steamsage.decision/2`，只因為容許差距欄位在 3.0.0 為 null（FR-008）。
  - 台幣換算（原價、現價、以分計算）與 004 的 `notes` 機制。

## Clarifications

### Session 2026-09-26（specify 前，與使用者確認，回答 HANDOFF.md §4）

- Q: 下一個 feature 做哪個方向？ → A: 等待成本。它直接回答核心問題，也能用 004 的「照建議買」評估。
- Q: 等待成本用什麼形式？ → A: 每月固定 NT$c，所有遊戲相同。不做每款遊戲各自的設定（YAGNI）。
  便宜的遊戲因此很少值得等，昂貴的遊戲可以等比較久。
- Q: 等待成本取代現行規則的哪些部分？ → A: 取代容許差距（`gap_pp_shallow`、`gap_pp_deep`、`gap_boundary_pct`、
  `tolerance_min_twd`、`tolerance_max_twd`）；12 個月範圍保留為規則常數，因為超過 12 個月的建議無法用台灣區資料驗證。
- Q: 「期望多省」怎麼算？ → A: 期望值，以機率加權，用模型的完整曲線，不用 50% 門檻；原因說明中仍列出機率。

### Session 2026-09-26（spec 初稿後）

- Q: 規則回測的「照建議買」以哪一種行動方式判定？ → A: 兩種都列，以「每月重新評估」判定：每個分析時點改照當時最新的決策行動，
  最接近每天更新報告的實際用法。004 的「固定決策」保留作為對照（FR-011）。
- Q: 換版的硬門檻？ → A: 驗證組上，以預設的 c 與「每月重新評估」計算，3.0.0 的平均淨效益比 2.0.0 高，而且 95% 區間不含 0；
  另外需要使用者同意。其他 c 值只報告（FR-015）。

### Session 2026-09-26（clarify）

- Q: c 的預設值用哪一份資料決定？驗證組比較之後改 c 算不算一次比較？ → A: 只用調參組的原型與願望清單的試算決定，
  在驗證組比較之前定案；比較之後改 c，算一次新的比較（計入最多 3 次），並記錄原因（FR-001、FR-014）。
- Q: 報告的「等待對照表」在新規則下顯示什麼？ → A: 改成每場一列，一直列到 12 個月內的最後一場。
  每列是「最晚等到這一場」時最好的選項：目標價、機率、期望多省、等待成本、淨效益；選中的那一列要標示；
  第一列是「現在買」，淨效益為 0（FR-007、FR-008）。
- Q: 使用者改了 c 之後，和前一天紀錄比較的變動標示怎麼處理？ → A: 照常標示變動，並在報告頁首註明「等待成本從 NT$X
  改成 NT$Y，本次的變動包含設定改變的影響」，做法和換模型版本相同（FR-023）。

### Session 2026-09-26（plan 原型後，只用調參組；見 research R0）

- Q: c 的預設值？ → A: **NT$20／月**。調參組（每月重新評估）：3.0.0 平均多省 NT$201、多等 19 天；2.0.0 為 NT$211、41 天；
  以 c = 20 計算淨效益 +4.0（95% 區間 [+2.2, +5.7]）。願望清單：現在買 18、即將到價 41、繼續等 4、低信心 2（FR-001）。
- Q: 到期沒達到目標時，期望值以什麼價格計算？ → A: **原價**，在最晚那一場結束時買（規則常數）。
  「現價」在回測中幾乎相同，但會高估正在打折的遊戲等下去的價值；「沒達到時的最深較淺折扣」太樂觀，已排除（FR-004）。
- Q: 甜蜜時點用哪一場？ → A: **最晚那一場以前，累積機率第一次 ≥ 50% 的那一場**，另外寫出最晚等到哪一場（FR-006）。

### Session 2026-09-26（analyze 後，使用者同意依建議修改）

- 硬門檻的「預設的 c」是程式中的預設值 NT$20，不是設定檔當下的值（FR-015）。
- 平手規則和 research R1 一致（FR-003）；期望值先四捨五入成整數分再比較（FR-005）。
- 從沒打折過的遊戲沿用 2.0.0 的「沒有本身歷史」路徑（Edge Cases）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 依等待成本決定現在買還是等 (Priority: P1)

使用者在設定檔填入等待成本，例如「每多等一個月要多省 NT$30」。報告中每款遊戲的建議，是比較「現在買」與「等到未來 12 個月內
某一場季節特賣」之後，淨效益最高的選項。原因說明寫出每個主要選項的期望多省、等待成本與機率，使用者看得懂為什麼要等或不等。

**Why this priority**: 這是本 feature 的核心。沒有它，後面的回測與換版沒有東西可比。

**Independent Test**: 在人工構造的機率曲線上執行規則 3.0.0，每個選項的期望多省、等待成本與淨效益和手算一致；
改變 c 時，建議的等待時間照預期變化（c 越高，等得越短）。

**Acceptance Scenarios**:

1. **Given** 一款原價 NT$188 的遊戲，下一場與再下一場的期望價格只差約 NT$9，c = NT$30，**When** 決策，
   **Then** 建議不等到再下一場；原因說明多等約 3 個月的等待成本約 NT$90，高於期望多省。
2. **Given** 一款原價 NT$1,990 的遊戲，9 個月後的特賣期望多省明顯超過 9 × c，**When** 決策，**Then** 建議等到那一場，
   原因列出期望多省、等待成本、淨效益與達到目標折扣的機率。
3. **Given** 現價已經有折扣，任何等待選項的淨效益都不高於現在買，**When** 決策，**Then** 分組為「現在買」，
   原因說明等下去最好的選項淨效益是多少、為什麼不划算。
4. **Given** 同一條曲線，**When** c 從 0 逐步提高，**Then** 建議的等待時間不會變長；c = 0 時選期望多省最高的選項；
   c 夠高時選現在買或最近的一場。
5. **Given** 某個選項「有 40% 機率多省 NT$300」，**When** 計算期望多省，**Then** 這 40% 的機率照比例計入，
   不會因為沒達到 50% 而被忽略。

### User Story 2 - 用回測判斷新規則是不是真的比較好 (Priority: P1)

開發者用規則回測在同一份資料上並列 2.0.0 與 3.0.0：照建議買多省多少、多等多久，以及扣掉等待成本之後的淨效益。
除了使用者選定的 c，也在數個不同的 c 值下並列，看結論穩不穩定。規則常數只在調參組上調，換版與否在驗證組上判定。

**Why this priority**: 憲章 IV 要求規則變更有回測依據。3.0.0 是依期望值設計的，只有在模型的機率夠準時才會真的多賺；
這必須用實際價格驗證，不能只看設計。

**Independent Test**: 用已知價格路徑的人工資料跑規則回測，每個決策的實際多省、實際多等天數與淨效益都和手算一致；
兩個規則版本的結果用同一份資料集、同一個模型與同一個 c。

**Acceptance Scenarios**:

1. **Given** 台灣區回測資料集的調參組，**When** 以某個 c 分別執行 2.0.0 與 3.0.0 的規則回測，**Then** 報告列出兩者的
   平均多省、平均多等、平均淨效益，以及兩者的差距與 95% 區間。
2. **Given** 數個 c 值，**When** 並列，**Then** 每個 c 都有兩個規則版本的淨效益與差距，並列在同一張表。
3. **Given** 規則常數已在調參組上定案，**When** 在驗證組上比較，**Then** 比較文件多一筆紀錄，寫明這是第幾次、
   用哪個 c、兩個版本的結果與判定。
4. **Given** 驗證組的判定，**When** 使用者看過並列結果，**Then** 使用者決定是否換上 3.0.0，決定附加到比較文件。

### User Story 3 - 報告顯示等待划不划算 (Priority: P2)

使用者打開報告，除了原本的甜蜜價與甜蜜時點，還能看到：建議的選項期望多省多少、要等多久、等待成本多少、淨效益多少，
以及和「現在買」、「等到下一場」相比如何。報告頁首寫出目前的等待成本設定，並標示為使用者偏好。

**Why this priority**: 決策改變之後，使用者必須看得到新依據，才能判斷要不要信任建議。

**Independent Test**: 產生報告，每款可決策的遊戲都有期望多省、等待成本、淨效益與機率；
報告的數值和決策輸出完全相同（憲章 VII）；改變 c 後重新產生，頁首與數值跟著改變。

**Acceptance Scenarios**:

1. **Given** 換上 3.0.0 後的報告，**When** 檢視任一款「繼續等」的遊戲，**Then** 可以看到建議的時點、目標價、
   達到的機率、期望多省、等待成本與淨效益。
2. **Given** 同一款遊戲的等待對照表，**When** 檢視，**Then** 第一列是「現在買」，之後每場一列，列到 12 個月內的最後一場，
   選中的那一列有標示，看得出多等一場值不值得。
3. **Given** 報告頁首，**When** 檢視，**Then** 看得到 c 的值與「使用者偏好」字樣，以及規則版本。
4. **Given** 上一次正式紀錄使用 2.0.0，**When** 產生新報告，**Then** 變動標示照常比較，並註明規則版本改變（003 FR-021）。

### User Story 4 - 換上新規則後，文件與數字一致 (Priority: P2)

使用者同意換版後，現行規則改成 3.0.0，完整資料集的規則回測重跑，模型定義與報告引用的數字一起更新。

**Why this priority**: 這是改進送到使用者手上的一步，也是憲章 V（規則單一正本）的要求。

**Independent Test**: 換版後，報告與正式紀錄的規則版本是 3.0.0；報告引用的回測數字與模型定義一致；
測試檢查程式中的回測常數與模型定義相同。

**Acceptance Scenarios**:

1. **Given** 換版完成，**When** 執行一鍵更新，**Then** 報告與正式紀錄使用 3.0.0，各組標題的數字來自 3.0.0 的規則回測。
2. **Given** 換版完成，**When** 檢視設定檔與報告，**Then** 3.0.0 不再使用容許差距的偏好；報告不顯示那些偏好。
3. **Given** 使用者決定不換，**When** 本 feature 結束，**Then** 現行規則維持 2.0.0，並列結果與使用者的決定寫進比較文件。

### Edge Cases

- **現價未知**：沒有現價時無法判斷「現在買」。以原價當作「現在買」的價格計算其他選項的期望多省，加上標籤與原因，
  分組不得為「現在買」（沿用 003 的 `price-unknown`）。
- **現價已低於所有選項的期望價格**：所有等待選項的期望多省都是負的，建議現在買。
- **淨效益相同**：現在買優先；等待選項之間同一場選較淺的目標、不同場選較早的一場（FR-003）。
- **c = 0**：只比期望多省，等待不扣分；結果 MUST 仍在 12 個月範圍內。
- **c 非常高**：幾乎一律現在買或等下一場；不得出錯。
- **c 不是有效值**（負數、非數字）：設定檔錯誤，照 003 的設定檢查拒絕執行並說明原因，不得默默改用預設值。
- **低信心遊戲**：同樣以等待成本決策，但曲線是整體比例、分組仍為「低信心」，原因沿用 003 的低信心說明。
  報告引用的低信心回測數字 MUST 來自 3.0.0 的規則回測。
- **原價與價格歷史不一致**（例如 Dying Light）：沿用 003，以目前原價換算、決策為低信心。
- **從沒打折過、曲線上沒有任何折扣**：沿用 2.0.0 的路徑（research R1）：一般信心、但 12 個月內沒有任何折扣達到 50% 時，
  改用「沒有本身歷史」的曲線，決策為低信心；不得當成錯誤。
- **12 個月內沒有季節特賣**：沿用 003，記為 `decision-error` 並附原因。
- **選項沒有達到目標**：等待選項的期望價格 MUST 計入「沒達到目標」的情況。不得假設沒達到時仍以目標價買到，
  那會高估等待的價值（FR-004）。
- **即將開始或正在進行的季節特賣**：沿用 002 與 003：正在進行的折扣就是現價，不列入曲線。
- **使用者改了 c，但沒有對應的回測**：報告引用的回測數字是以某個 c 算出來的；當前的 c 沒有對應的回測時，
  MUST 註明數字來自哪個 c，或不引用數字（FR-020）。
- **並列比較中 2.0.0 仍需要容許差距**：2.0.0 保留原本的偏好值，只用於並列回測，不顯示在 3.0.0 的報告中。

## Requirements *(mandatory)*

### Functional Requirements

**等待成本偏好**

- **FR-001**: 系統 MUST 提供使用者偏好「等待成本」c：每多等一個月要多省的台幣，所有遊戲同一個值，存在設定檔中。
  c MUST 明確標示為使用者偏好（憲章 VI），每份決策輸出與正式紀錄 MUST 記錄當次的值。
  預設值在 plan 階段以原型試算數個值之後由使用者決定，寫進模型定義。試算只用調參組與願望清單，
  預設值 MUST 在驗證組比較之前定案（FR-014）。
- **FR-002**: 規則 3.0.0 MUST NOT 使用容許差距的偏好（`gap_pp_shallow`、`gap_pp_deep`、`gap_boundary_pct`、
  `tolerance_min_twd`、`tolerance_max_twd`）。這些偏好只為並列回測 2.0.0 而保留，設定檔與模型定義 MUST 註明這一點。

**決策規則 3.0.0**

- **FR-003**: 規則 3.0.0 MUST 比較以下選項，選淨效益最高者：
  - **現在買**：以現價買，等 0 個月，淨效益為 0。
  - **等待選項**：以某個目標折扣，最晚等到未來 12 個月內的某一場季節特賣。範圍沿用規則常數 12 個月。
  - 淨效益 = 期望多省 − c × 期望多等的月數。期望多省 = 現價 − 期望實付價格。
  - 淨效益相同時現在買優先；等待選項之間，同一場選較淺的目標（機率較高），不同場選較早的一場（research R1）。
- **FR-004**: 期望實付價格與期望等待時間 MUST 由模型的機率曲線以機率加權計算，包含三種情況：
  在各場特賣達到目標、提早以更深的折扣達到目標，以及到期都沒達到。沒達到時的實付價格與等待時間 MUST 有明確定義，
  不得假設仍以目標價買到。定義方式在 plan 階段以原型比較候選做法，只在調參組上選定，寫進模型定義（規則常數，憲章 VI）。
  plan 階段已選定：**到期沒達到時，以原價在最晚那一場結束時買**（research R2）。
- **FR-005**: 規則 3.0.0 MUST 只讀曲線、原價、現價與偏好，不讀資料庫與時鐘（沿用 003）；價格以整數分計算。
  期望值是機率加權的結果，MUST 先四捨五入成整數分再比較，讓平手的判斷是確定的。
- **FR-006**: 為了和 003 的報告與分組相容，選中的等待選項 MUST 對應到「甜蜜價」（目標折扣的價格）與「甜蜜時點」，
  分組照 003：現在買、低信心、即將到價（甜蜜時點在前 `soon_sales` 場）、繼續等。
  - **甜蜜時點** = 最晚那一場以前，「≥ 目標折扣」的累積機率第一次 ≥ 50% 的那一場（和 2.0.0 同一個門檻）；
    沒有任何一場達到 50% 時，才是最晚的那一場。
  - 決策與報告 MUST 同時寫出「最晚等到哪一場」。
  - 理由（plan 原型）：延長期限的代價很小（目標提早達到就提早買），選中選項的最晚一場幾乎都是 12 個月內的最後一場；
    如果把它當甜蜜時點，「即將到價」與到價率就失去意義（research R3）。
  12 個月內最低價（P_min）MAY 繼續顯示作為參考，但 MUST NOT 影響 3.0.0 的選擇。
- **FR-007**: 決策原因 MUST 說明：
  - 選中的選項：目標價、最可能到價的那一場與機率、最晚等到哪一場與到期前達到的機率、期望多省、期望多等的時間、
    等待成本與淨效益。
  - 到期沒達到時以原價計算（規則常數）。
  - 至少一個被放棄的對照選項（例如現在買、等到下一場，或期望多省最高的選項），以及為什麼淨效益較低。
  - c 的值，並標示為使用者偏好。
  - 特殊情況（現價未知、從沒打折過、低信心、原價不一致）的措辭 MUST 在真實資料上抽查（004 的教訓）。
- **FR-008**: 決策輸出 MUST 記錄選中選項與主要對照選項的期望多省、期望等待、等待成本、淨效益與機率，以及 c 的值。
  呈現層只讀這些欄位，不得自行重算（憲章 VII）。規則 3.0.0 不使用容許差距，相關欄位沒有意義，
  所以決策輸出契約升為 `steamsage.decision/2`（容許差距欄位在 3.0.0 為 null）；舊的 `/1` 紀錄 MUST 仍可讀取與比較
  （contracts/decision-output-v2.md）。
  - **等待對照表**：規則 3.0.0 的決策 MUST 輸出每場一列的對照表，列到 12 個月內的最後一場。
  - 第一列是「現在買」：以現價買，淨效益為 0。
  - 其他每一列是「最晚等到這一場」時淨效益最高的選項：目標價、達到的機率、期望多省、等待成本與淨效益。
  - 選中的那一列要標示。報告以這張表取代 003 的 50% 價格表。
- **FR-009**: 規則版本 MUST 升為 `sweet-price` 3.0.0；2.0.0 與 1.0.0 保留，可用於並列回測。規則常數與使用者偏好的區分照 003。

**規則回測**

- **FR-010**: 規則回測 MUST 能指定規則版本與 c 執行，並在「照建議買」加上：
  - 每次決策的淨效益 = 實際多省 − c × 實際多等的月數。
  - 淨效益的平均、中位數、25 與 75 百分位，依分組、信心與全體彙總。
  - 既有的多省、多等、事後最低價與截斷數照舊列出。
- **FR-011**: 「照建議買」的行動方式 MUST 對 2.0.0 與 3.0.0 相同，才能公平比較。兩種方式都要列出，**以「每月重新評估」判定**：
  - **每月重新評估**（判定用，最接近每天更新報告的實際用法）：從分析時點開始照當時的決策行動。
    - 決策為現在買：以現價買。
    - 否則，價格一旦進入當時決策的甜蜜價就買。
    - 到下一個分析時點（每月 1 日）改照那時的新決策，新決策為現在買就以那時的現價買。
    - 12 個月內都沒買，以 12 個月時的價格買；資料不足 12 個月又還沒買的，算截斷。
  - **固定決策**（沿用 004 FR-021，供對照）：照第一次的決策等到甜蜜價，12 個月內沒到就以 12 個月時的價格買。
- **FR-012**: 並列報告 MUST 在同一份資料集、同一個模型、同一個 c 下列出 2.0.0 與 3.0.0 的結果與差距；
  另外 MUST 列出數個 c 值（至少涵蓋 0、預設值，以及比預設值低和高的值）的並列表，看結論是否穩定。
  2.0.0 不使用 c，它的淨效益以同一個 c 計算。
- **FR-013**: 兩個規則版本的差距 MUST 附 95% 區間，依遊戲成對重抽樣（沿用 002 的比較方法與種子規則）。
- **FR-014**: 3.0.0 的規則常數（例如 FR-004 的「沒達到時」定義）MUST 只在調參組上選定；換版判定只看驗證組。
  驗證組的比較最多 3 次，每次在比較文件中記錄第幾次、改了什麼、為什麼改；3 次都沒有通過時，以「未優於」結束，
  現行規則不變（沿用 004 FR-013）。這個次數和 004 的模型比較分開計算。
  驗證組比較之後再改 c 的預設值，也算一次新的比較，並記錄原因。
- **FR-015**: 換版的條件，全部都要滿足：
  - **硬門檻**：在驗證組上，以預設的 c（程式中的預設值 NT$20，寫在模型定義；不是設定檔當下的值）與「每月重新評估」計算，3.0.0 的平均淨效益比 2.0.0 高，而且差距的 95% 區間不含 0。
  - 使用者看過並列結果後同意。其他 c 值與「固定決策」的結果只報告，不當硬門檻，由使用者判斷。
- **FR-016**: 並列報告 MUST 附上願望清單在兩個規則版本下的決策差異：各組款數、改變分組的遊戲，以及甜蜜價、甜蜜時點與
  期望淨效益的變化（沿用 004 的 `compare-rule`）。
- **FR-017**: 原型與並列報告 MUST 另外列出：如果範圍放寬到 24 個月與 5 年，願望清單與回測中各有多少決策會選擇超過 12 個月的
  選項，以及它們的期望多等時間。這只是參考，不改變 3.0.0 的 12 個月範圍，也不評估這些長期選項的實際結果。
- **FR-018**: 並列報告的結果與使用者的決定 MUST 附加寫入比較文件（只附加）。

**換版**

- **FR-019**: 換版後 MUST：
  - 在完整的台灣區回測資料集上以預設 c 重跑 3.0.0 的規則回測。
  - 更新模型定義的決策規則一節（規則、參數與依據、已知限制、規則回測、版本歷史）與程式中的規則回測常數，兩者一致。
  - 更新現行規則的設定；報告、決策輸出與正式紀錄記錄新的規則版本與 c。
- **FR-020**: 報告與決策中引用的規則回測數字 MUST 依（規則版本、模型與參數、c）對照。當前的 c 沒有對應的回測時，
  MUST 註明數字是以哪個 c 算出，或不引用數字；不得把其他 c 的數字當成當前設定的結果。
- **FR-021**: 現行規則 MUST 仍可在程式中切回 2.0.0，以便重跑比較或比對舊結果（沿用 004 FR-026）。
- **FR-022**: 004 由模型提供的限制提示（例如「12 個月內最低價可能更低」）MUST 依 3.0.0 的規則回測數字更新；
  文字 MUST 符合 3.0.0 的語意。
- **FR-023**: 和前一次正式紀錄比較時，如果 c 不同，變動標示 MUST 照常比較，報告頁首 MUST 註明「等待成本從 NT$X 改成 NT$Y，
  本次的變動包含設定改變的影響」（做法同 003 FR-021 的模型版本改變）。前一次紀錄沒有 c（規則 2.0.0 以前）時，只註明規則版本改變。

### Key Entities

- **等待成本 c**：使用者偏好，台幣／月，所有遊戲同一個值；記錄在每份決策輸出與正式紀錄中。
- **決策選項**：現在買，或（目標折扣、最晚的季節特賣）。每個選項有期望實付價格、期望等待時間、達到目標的機率、
  期望多省、等待成本與淨效益。
- **規則 3.0.0**：從選項中選淨效益最高者，對應到甜蜜價、甜蜜時點與分組。規則常數寫在程式與模型定義中。
- **淨效益回測**：每個分析時點照建議行動的實際多省、實際多等與淨效益，依規則版本與 c 彙總。
- **換版紀錄**：驗證組的比較、並列報告、使用者的決定與日期，附加在比較文件中。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在人工曲線上，每個選項的期望多省、期望等待、等待成本與淨效益 100% 和手算一致（以分為單位完全相同）。
- **SC-002**: 在人工曲線與真實願望清單上，c 提高時，每款遊戲建議的等待時間 100% 不增加；c = 0 時選中的選項期望多省最高。
- **SC-003**: 在人工價格路徑上，規則回測中每個決策的實際多省、實際多等與淨效益 100% 和手算一致。
- **SC-004**: 比較文件中有調參組與驗證組的並列紀錄：兩個規則版本在同一個 c 下的平均淨效益、差距與 95% 區間，以及
  至少 4 個 c 值的並列表。
- **SC-005**: 以現在為分析時點，願望清單中可決策的遊戲 100% 有選中選項的期望多省、等待成本、淨效益與機率，
  報告與決策輸出的數值 100% 相同。
- **SC-006**: 換版時（如果換）：模型定義、程式中的規則回測常數與報告引用的數字三者一致；報告與正式紀錄 100% 記錄
  規則版本與 c。
- **SC-007**: 願望清單的預測、決策加報告仍在 30 秒內完成（003 SC-006）；單一 c 的規則回測在完整資料集上 2 分鐘內完成
  （現行約 15 秒），數個 c 值的並列在 10 分鐘內完成。實際耗時寫入驗收文件。
- **SC-008**: 功能測試通過與「新規則是否較好」分開報告；後者只以驗證組的並列回測回答。

## Assumptions

- 模型維持 `seasonal-record` 1.0.0 `{min_sales=1, half_life=2, hazard_history=TW+US}`，曲線不變。
  3.0.0 的好壞取決於曲線的校準（模型定義：台灣區 0.8–0.9 那一格預測 0.860、實際 0.805），這正是回測要驗證的。
- 回測資料集沿用 002 的台灣區資料集（`d547c29d…`，2,528 款、20 個分析時點，資料截止 2026-09-25）與 004 的調參組／驗證組切分，
  鹽不變。如果需要更新資料截止時間，兩個規則版本 MUST 在同一截止時間上比較。
- 「一個月」以天數換算（365 / 12 天），決策與回測使用同一個換算；等待時間從分析時點算到實際（或預期）購買的那一刻。
  預期購買的時刻以該場季節特賣的開始為準，細節在 plan 定清楚並寫進模型定義。
- 模型只預測季節特賣；非季節折扣不在期望值中，所以等待選項的期望多省可能偏保守。這寫進已知限制。
- 期望值是風險中性的：「50% 機率多省 NT$200」和「確定多省 NT$100」看成一樣。使用者已選擇期望值（Clarifications）。
- 規則回測只能評估 12 個月內；3.0.0 的範圍也是 12 個月，所以沒有無法評估的建議。FR-017 的長期選項只列數量，不評估結果。
- 3.0.0 以 c 為目標設計，在同一個 c 下評估淨效益對它有利；因此並列報告同時列出多省與多等兩個原始指標，並在數個 c 值下比較，
  讓使用者看得出取捨，而不是只看淨效益。
- 本 feature 可能以「未優於」或「使用者決定不換」結束。這時交付的是 3.0.0 的實作、回測與比較紀錄，現行規則維持 2.0.0。
