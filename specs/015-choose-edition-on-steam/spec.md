# Feature Specification: 在 Steam 遊戲頁直接指定追蹤版本

**Feature Branch**: `015-choose-edition-on-steam`

**Created**: 2026-10-14

**Status**: Draft

**Input**: User description: "015 在 Steam 遊戲頁直接指定追蹤版本（Chrome 擴充功能 + 本機程式）。方案 B：按鈕直接生效，透過 Chrome native messaging 呼叫本機程式，
寫入 steamsage.toml 並重新產生報告。按鈕以 SweetSpot 遊戲頁面板新增的「版本」一節為主，Steam 自己的每個購買框加小按鈕當捷徑；願望清單頁與彈出視窗不放按鈕。
按下後面板顯示進度，完成後換成新版本的數字，失敗時顯示原因、設定檔不留半改的內容。本機程式只接受固定的少數指令，只允許這個擴充功能，
與每日背景更新共用寫入鎖；不安裝本機程式時其餘功能照常。"

## 範圍說明

feature 009 讓使用者在 `steamsage.toml` 的 `[purchase_options]` 指定一款遊戲要追蹤的購買選項（例如 Cyberpunk 2077 追蹤終極版）。
目前的流程是：打開 HTML 報告、在那款遊戲的「其他版本」表複製設定行、貼進設定檔、等下一次產生報告。使用者是在 Steam 網站上逛的時候
發現想換版本的（2026-10-14：Steam 頁面上本體 -70%，建議卻是「繼續等」，因為追蹤的是終極版 -60%），希望在同一個頁面上直接指定。

feature 011 的擴充功能刻意設計成只讀：只讀自己資料夾裡的資料檔、權限只有更新圖示用的計時器、禁止連到任何網站。瀏覽器擴充功能
本身不能修改電腦上的設定檔，所以這個 feature 新增一個**本機程式**，由擴充功能透過瀏覽器提供的本機程式通道呼叫。這是安全模型的改變：
擴充功能從「只顯示」變成「可以請本機程式改設定檔、重新產生報告」。本 spec 的安全需求（FR-013–FR-022）和功能需求同等重要。

2026-10-14 的檢查（唯讀）：

| 檢查 | 結果 |
|---|---|
| 報告的執行時間 | 當天背景更新的報告步驟約 6 秒（整個更新含資料抓取約 2 分鐘） |
| 可指定的版本 | 願望清單 69 款中 24 款另有版本，共 31 個；版本是否可指定由 009 的驗證決定（通過驗證才可指定） |
| 指定後的資料 | 通過驗證的版本每天都會抓台灣區價格歷史，所以指定後立刻可用；美國區（輔助證據）只抓指定生效的版本（009 FR-004），下一次每日更新才補上 |
| 遊戲頁的購買框 | 擴充功能已經會讀每個購買框的套件或組合包編號（011 頁面現價並列），可以用同樣的方式對應到版本 |

- **包含**：
  - 遊戲頁面板新增「版本」一節：列出這款遊戲的所有購買選項（目前追蹤的與其他版本），可以指定其中一個或改回 Steam 預設。
  - Steam 自己的購買框中的捷徑按鈕（只限可指定的版本）。
  - 本機程式：接受固定的指令，修改 `[purchase_options]` 中那一款遊戲的設定，重新產生報告，回報結果。
  - 本機程式的安裝與移除（只給這台電腦、這個使用者）。
  - 擴充功能資料檔多帶每款遊戲的版本清單（可指定與否、不可指定的原因、設定行）。
- **不包含**：
  - 願望清單頁、彈出視窗的指定按鈕（那兩處沒有版本清單）。
  - 指定按鈕以外的設定修改（偏好、其他區段）；不在追蹤範圍的遊戲；按下按鈕時重新抓取價格資料（只重新產生報告）。
  - Windows 以外的作業系統、Chrome 以外的瀏覽器。
  - 模型、決策規則、009 的指定規則本身（沿用 009 FR-005–FR-012）。

## Clarifications

### Session 2026-10-14

- Q: 從面板指定版本後重新產生的報告，要算正式執行（和手動執行 `report` 一樣）嗎？ → A: 算正式執行：存預測紀錄、推進變動基準、更新 HTML 報告與擴充功能資料檔，和手動執行 `report` 相同（FR-007、FR-012）。
- Q: 按下「追蹤這個版本」後，要先確認再執行嗎？ → A: 同一個按鈕按兩下確認：第一次按下變成「確定追蹤《…》？再按一次」，5 秒內沒有再按就恢復；不用對話框（FR-006）。另外只回應使用者真正的操作，頁面程式的模擬點擊不算（FR-006a）。
- Q: 擴充功能什麼時候檢查本機程式是否可用？ → A: 展開「版本」一節時檢查一次（預設收合），同一頁沿用結果；購買框的捷徑在第一次按下時檢查（FR-001、FR-023a）。
- Q: 「預設決定」一節的三點（同步等待報告、報告失敗就還原設定、對預設版本按下等同改回預設），都照寫的做嗎？ → A: 三點都照寫的做（FR-003、FR-009、FR-010、FR-011）。

## 預設決定（撰寫 spec 時所做，2026-10-14 使用者確認）

使用者的描述沒有決定的三點，依下列理由選定，2026-10-14 經使用者確認。

- **報告同步等待**（而不是只寫設定、另外提供「立即重新產生」）：報告步驟實測約 6 秒；超過時限時照 FR-010 處理。
- **報告失敗時還原設定**（而不是保留設定、等下一次更新生效）：使用者要求「設定檔不留半改的內容」；保留會讓設定與畫面上的數字不一致，
  直到下一次更新。
- **對 Steam 預設版本按「追蹤這個版本」等同「改回 Steam 預設」**：移除那款遊戲的設定行，不寫一行和預設相同的指定（009 對兩者的結果相同，
  但多一行會讓日後 Steam 換預設時仍固定在舊的那一個，009 FR-006）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 在遊戲頁面板指定或改回版本，立即生效 (Priority: P1)

使用者在 Steam 遊戲頁看 SweetSpot 面板，展開「版本」一節，看到這款遊戲的每個購買選項、現價、哪個是目前追蹤的。按下另一個版本的
「追蹤這個版本」，面板顯示進度，幾秒後面板換成那個版本的現價、甜蜜價、甜蜜時點與分組，並標示「追蹤中（使用者指定）」。
之後想恢復，按「改回 Steam 預設」即可。

**Why this priority**: 這是整個 feature 的目的；沒有它，其他故事都沒有意義。

**Independent Test**: 安裝本機程式，在人工資料與測試用設定檔上，從面板指定一個版本、再改回預設，檢查設定檔的變化、報告與面板的數字。

**Acceptance Scenarios**:

1. **Given** Cyberpunk 2077 追蹤 Steam 預設（本體），終極版可指定，**When** 在面板的「版本」按終極版的「追蹤這個版本」並在 5 秒內再按一次確認，
   **Then** 設定檔的 `[purchase_options]` 多一行 `1091500 = "bundle/32470"`，其他內容不變；報告重新產生；面板換成終極版的數字並標示追蹤中。
2. **Given** Cyberpunk 2077 已指定終極版，**When** 按「改回 Steam 預設」，**Then** 那一行被移除，其他內容不變，面板換成本體的數字。
3. **Given** 設定檔中已有 Cyberpunk 2077 的指定，**When** 指定另一個版本，**Then** 原本那一行被改成新的值，不出現兩行。
4. **Given** 面板正在等待結果，**When** 報告完成，**Then** 面板從進度提示換成新的內容，不需要使用者重新整理頁面。
5. **Given** 某個版本未通過 009 的驗證，**When** 看「版本」一節，**Then** 那個版本列出但沒有按鈕，旁邊寫出不能指定的原因。
6. **Given** 按了一次「追蹤這個版本」，**When** 5 秒內沒有再按，**Then** 按鈕恢復原狀，沒有送出任何請求，設定檔不變。
7. **Given** 頁面上的程式對按鈕觸發模擬點擊，**When** 連續觸發兩次，**Then** 沒有送出任何請求。

---

### User Story 2 - 沒有安裝本機程式時，其他功能照常並告訴使用者怎麼做 (Priority: P1)

使用者還沒安裝本機程式，或安裝的程式失效（例如擴充功能資料夾搬家後編號改變）。擴充功能的彈出視窗、願望清單行、遊戲頁面板
都和現在一樣；「版本」一節照樣列出版本，但按鈕換成一句說明：如何安裝本機程式，以及可以手動貼到設定檔的那一行。

**Why this priority**: 擴充功能目前每天在用；新功能不能讓它在沒安裝本機程式時退化（憲章 III 的精神）。

**Independent Test**: 不安裝本機程式，跑 011 現有的端對端檢查全部通過，面板的「版本」一節顯示安裝說明與設定行。

**Acceptance Scenarios**:

1. **Given** 沒有安裝本機程式，**When** 打開有其他版本的遊戲頁並展開「版本」一節，**Then** 面板其他內容不變，「版本」一節顯示安裝方式與每個可指定版本的設定行。
2. **Given** 沒有安裝本機程式，**When** 使用彈出視窗與願望清單頁，**Then** 行為與本 feature 之前完全相同。
3. **Given** 本機程式已安裝，**When** 打開遊戲頁但沒有展開「版本」一節、也沒有按捷徑，**Then** 本機程式沒有被啟動。

---

### User Story 3 - 本機程式只做被允許的事 (Priority: P1)

本機程式會修改設定檔、執行報告，所以它必須只接受這個擴充功能送來、格式正確、內容在允許範圍內的請求；其他一律拒絕，而且拒絕時
不留下任何變更。

**Why this priority**: 這是安全模型改變的前提；沒有它就不應該安裝本機程式。

**Independent Test**: 直接對本機程式送一組惡意或錯誤的請求（未知指令、多餘欄位、路徑、超長內容、不在資料中的遊戲、不是這款遊戲的版本），
檢查每個都被拒絕、設定檔與資料庫逐位元組不變、記錄中有拒絕原因且沒有金鑰。

**Acceptance Scenarios**:

1. **Given** 請求的指令不在允許清單，**When** 送給本機程式，**Then** 回覆拒絕原因，不讀寫設定檔、不執行報告。
2. **Given** 請求的遊戲不在目前的追蹤範圍，或版本不是這款遊戲可指定的購買選項，**When** 送出，**Then** 拒絕，設定檔不變。
3. **Given** 每日背景更新正在執行，**When** 送出指定請求，**Then** 回覆「背景更新進行中，請稍後再試」，不等待也不修改任何檔案。
4. **Given** 設定檔有語法錯誤，**When** 送出指定請求，**Then** 拒絕並說明設定檔需要先修正，不改寫它。

---

### User Story 4 - 在 Steam 自己的購買框直接按 (Priority: P3)

使用者看著 Steam 的「購買 《電馭叛客 2077：終極版》」框時，框裡有一個小按鈕「SweetSpot：追蹤這個版本」，目前追蹤的那個框標示「SweetSpot：追蹤中」。
按下的效果與面板的按鈕相同，結果顯示在 SweetSpot 面板上。

**Why this priority**: 方便的捷徑；面板的按鈕已經能完成同樣的事，而且 Steam 改版時這裡可能找不到位置。

**Independent Test**: 在測試用的遊戲頁上，可指定版本的購買框有按鈕、DLC 與原聲帶等不是版本的框沒有、頁面結構不符時一個都不放。

**Acceptance Scenarios**:

1. **Given** 遊戲頁有本體、終極版、原聲帶三個購買框，**When** 頁面載入，**Then** 本體與終極版的框有按鈕或「追蹤中」標示，原聲帶沒有。
2. **Given** 購買框的結構改變（找不到套件或組合包編號），**When** 頁面載入，**Then** 不放任何捷徑按鈕，頁面不變，面板的按鈕照常可用。

---

### Edge Cases

- **同時按了兩次或在兩個分頁各按一次**：一次只處理一個請求；第二個請求在第一個完成前回覆「上一個指定還在處理」，不排隊、不合併。
- **擴充功能的資料比設定檔舊**（使用者剛手動改過設定檔、還沒重新產生報告）：本機程式以按下當時的設定檔與資料庫為準驗證並修改；
  面板最後顯示的是重新產生後的結果。
- **指定的版本在按下之前剛下架或驗證失效**：本機程式驗證時拒絕，說明原因；設定檔不變。
- **報告產生成功，但擴充功能資料檔寫入失敗**：視為失敗，設定檔、報告與資料檔還原，已保存的正式紀錄保留（FR-009）。
- **報告超過時限**（FR-010）：面板顯示「報告仍在產生，完成後重新整理頁面即可看到」；本機程式繼續完成或還原，不讓設定檔停在半改狀態。
- **指定後美國區歷史尚未取得**：照 009 的既有說明顯示（美國區輔助證據下一次每日更新後補上），不視為失敗。
- **使用者擁有這款遊戲**：面板收合時「版本」一節一起收合；展開後仍可指定（例如想追蹤終極版的價格）。
- **設定檔沒有 `[purchase_options]` 區段**：第一次指定時新增這個區段，其他內容不變。
- **設定檔中那一行有行尾註解或特殊格式**：改寫或移除那一行時，行尾註解一起處理掉，不影響其他行；其他行的註解、空行、順序都不變。
- **Steam 預設版本改變**（006 版本更換）：「版本」一節依最新資料列出；已指定的遊戲照 009 FR-006 繼續追蹤指定的版本。
- **專案資料夾搬家**：擴充功能編號固定（plan 決定 D1），但本機程式的啟動檔指向舊位置，面板顯示本機程式無法使用、需要重新安裝（US2）。

## Requirements *(mandatory)*

### Functional Requirements

**版本一節與按鈕**

- **FR-001**: 遊戲頁面板 MUST 新增「版本」一節，列出這款遊戲在最新報告中的所有購買選項：目前追蹤的那一個與 009 的其他版本，
  每個顯示名稱、現價與折扣，並標示哪一個是 Steam 預設、哪一個是目前追蹤的（Steam 預設或使用者指定）。只有一個購買選項的遊戲不顯示這一節。
  這一節預設收合（標題顯示版本數）；展開前 MUST NOT 啟動本機程式。
- **FR-002**: 可指定的版本（通過 009 FR-003 驗證）MUST 有「追蹤這個版本」按鈕；目前追蹤的版本標示「追蹤中」；使用者指定生效時另有
  「改回 Steam 預設」。不可指定的版本 MUST 列出但不給按鈕，並寫出 009 的原因。
- **FR-003**: 對 Steam 預設版本按「追蹤這個版本」MUST 等同「改回 Steam 預設」。
- **FR-004**: 遊戲頁上，Steam 自己的購買框中，對應到可指定版本的框 MUST 有捷徑按鈕，對應到目前追蹤版本的框標示「追蹤中」；
  對應以套件或組合包編號比對（和 011 頁面現價並列相同）。對應不到版本的框（DLC、原聲帶等）不放；頁面結構不符時一個都不放、頁面不變（沿用 011 FR-016）。
- **FR-005**: 願望清單頁、彈出視窗 MUST NOT 有指定按鈕；它們維持 011 與 2026-10-14「指定版本」小標的行為。

**按下之後**

- **FR-006**: 「追蹤這個版本」與「改回 Steam 預設」（面板與購買框的捷徑都一樣）MUST 按兩下才執行：第一次按下，按鈕變成
  「確定追蹤《版本》？再按一次」（改回時為「確定改回 Steam 預設？再按一次」），5 秒內再按同一個按鈕才送出；逾時或按了別處就恢復原狀，不送出任何請求。
- **FR-006a**: 只有使用者真正的滑鼠或鍵盤操作 MUST 能觸發送出；Steam 頁面上的程式以模擬點擊或事件觸發的，MUST NOT 送出請求。
- **FR-006b**: 確認送出後 MUST 立即在面板顯示進度（例如「正在指定《…》並重新產生報告…」），期間停用這款遊戲的所有指定按鈕，避免重複送出。
- **FR-007**: 本機程式 MUST 依序：檢查請求格式（FR-014、FR-015）→ 取得處理鎖與寫入鎖（FR-018、FR-019）→ 以當下的設定檔與資料庫驗證（FR-016、FR-017）→ 修改設定檔中那一款遊戲的設定 → 重新產生正式報告
  （正式執行，和手動執行 `report` 相同：存預測紀錄、推進變動基準、寫 HTML 報告與擴充功能資料檔；MUST NOT 另設一種不存紀錄的執行模式）→ 回覆結果。
  重新產生的報告中，這款遊戲照現行規則出現版本更換的變動標示。
- **FR-008**: 設定檔的修改 MUST 只影響 `[purchase_options]` 中那一款遊戲的那一行（新增、改寫或移除）；其他所有內容（其他區段、其他遊戲、
  註解、空行、順序、編碼）MUST 逐位元組不變。寫入 MUST 是完整替換（不會留下寫到一半的檔案）。
- **FR-009**: 驗證之後任何一步失敗（設定檔寫入、報告產生、擴充功能資料檔寫入），設定檔 MUST 還原為按下之前的內容（逐位元組相同），
  回覆的原因 MUST 說明失敗在哪一步；既有的報告與資料檔維持上一次成功的版本（憲章 III）。
  這次執行已經保存的正式紀錄 MUST 保留、不刪除（憲章 IV）；下一次正式報告照現行規則標示這款遊戲的版本更換。
- **FR-010**: 面板等待結果 MUST 有時限（預設 60 秒）。超過時面板顯示「報告仍在產生，完成後重新整理頁面即可看到」；本機程式 MUST 繼續把
  這次請求做完或還原，不因面板不再等待而中斷在半途。
- **FR-011**: 成功時面板 MUST 自動換成重新產生後的內容（現價、甜蜜價、甜蜜時點、分組、版本一節、原因），不需要重新整理頁面；
  其他已開啟的 Steam 分頁在重新整理後顯示新內容。
- **FR-012**: 每次指定或改回 MUST 和手動修改設定檔的結果完全相同：重新產生的報告與擴充功能資料檔，和「手動寫同一行再執行 `report`」
  在相同資料上一致（沿用 009 的指定規則，不另設規則）。

**本機程式的安全邊界**

- **FR-013**: 本機程式 MUST 只透過瀏覽器的本機程式通道接受請求，且只接受這個擴充功能（以安裝時登記的擴充功能編號）送來的請求；
  不開啟任何網路連接埠、不連任何網站。
- **FR-014**: 本機程式 MUST 只接受三種指令：查詢狀態（是否可用、設定檔中這款遊戲目前的指定；資料時間由擴充功能資料檔提供）、指定版本（遊戲編號＋套件或組合包編號）、改回 Steam 預設（遊戲編號）。
  請求 MUST 符合固定格式（欄位、型別、長度上限）；未知指令、多餘或缺少的欄位、超過長度的請求 MUST 拒絕。
- **FR-015**: 請求中 MUST NOT 有任何檔案路徑、指令列、程式碼或設定檔內容；本機程式要讀寫的檔案與要執行的動作都是固定的
  （這台電腦上的 SweetSpot 設定檔、資料庫與報告），不由請求決定。
- **FR-016**: 指定請求的遊戲 MUST 在目前的追蹤範圍（009 FR-008 的範圍），版本 MUST 是這款遊戲在資料庫最新紀錄中可指定的購買選項；
  驗證以本機程式按下當時讀到的資料為準，不信任擴充功能送來的名稱或價格。
- **FR-017**: 設定檔無法解析時 MUST 拒絕並說明需要先修正設定檔，不改寫它。
- **FR-018**: 一次只處理一個請求；處理中收到的新請求 MUST 立即拒絕（「上一個指定還在處理」）。
- **FR-019**: 本機程式 MUST 使用和每日更新（`update`）相同的寫入鎖；鎖被占用（例如 02:30 背景更新進行中）時 MUST 立即拒絕並說明，
  不等待、不修改任何檔案。`report` 本身不取寫入鎖（003 research R9），所以本機程式和另一個正式 `report` 同時執行的情況不排除，
  和手動 `report` 與背景更新的 `report` 可以同時執行相同（2026-10-14 plan 決定 D4）。
- **FR-020**: 每個請求 MUST 記錄到 SweetSpot 的日誌：時間、指令、遊戲、版本、結果與原因。API 金鑰 MUST NOT 出現在任何回覆、日誌或錯誤訊息中（憲章 IX）。
- **FR-021**: 擴充功能 MUST 只多要求使用本機程式通道所需的權限；仍然 MUST NOT 連到任何網站（011 的連線限制與「擴充功能發出的請求為 0」維持）。
- **FR-022**: 本機程式的安裝與移除 MUST 各用一個指令完成，只影響目前使用者（不需要系統管理員權限）；安裝時登記擴充功能編號，移除時清除所有登記。
  安裝說明 MUST 寫在 README，並說明這個程式能做與不能做的事。

**沒有本機程式時**

- **FR-023**: 本機程式未安裝或無法使用時，擴充功能的所有既有功能 MUST 照常；「版本」一節 MUST 照常列出版本，按鈕換成「安裝本機程式後可在這裡指定」
  的說明，並顯示每個可指定版本的設定行（和報告「指定」欄相同），讓使用者可以手動貼到設定檔。
  （2026-10-22 稽核補記：2026-10-14 使用者驗收後由 commit 5925272 改掉）「安裝本機程式後可在這裡指定」一句換成一節最上面的安裝說明（在哪個資料夾執行 `uv run sweetspot host install`；無法使用時附 Chrome 的訊息），
  每個版本改為手動步驟（打開哪個設定檔、加哪一行或刪哪一行、存檔後執行 更新資料.cmd）；送出後才發現本機程式不在（`not-installed`）時說「找不到本機程式（可能已經移除），沒有改任何設定」。
  文字見 [contracts/extension-ui.md](contracts/extension-ui.md)「版本」一節與「按兩下確認」的補記（extension/lib.js）。
- **FR-023a**: 擴充功能 MUST 在使用者展開「版本」一節時查詢一次本機程式的狀態，同一頁沿用結果；購買框的捷徑在第一次按下時查詢，
  無法使用時捷徑改為「需要安裝本機程式（見 SweetSpot 面板）」並展開面板的「版本」一節。沒有展開、也沒有按捷徑的頁面 MUST NOT 啟動本機程式。

**資料**

- **FR-024**: 擴充功能資料檔 MUST 為每款遊戲帶上版本清單：購買選項的種類與編號、名稱、現價與折扣、是否為 Steam 預設、是否為目前追蹤、
  是否可指定、不可指定的原因、設定行。只新增欄位，既有欄位與格式識別不變，舊版擴充功能讀到新資料仍照常運作。
- **FR-025**: 資料檔中的版本名稱與原因（來自 Steam 與 ITAD 的文字）MUST 只當文字顯示，不得當成標記或程式執行（憲章 IX）。

### Key Entities

- **版本選項**：一款遊戲的一個購買選項（套件或組合包），帶名稱、現價、是否為 Steam 預設、是否為目前追蹤、是否可指定與原因、設定行。
  來自 009 的購買選項紀錄與驗證結果。
- **指定請求**：擴充功能送給本機程式的一個指令（查詢狀態、指定版本、改回預設）及其結果（成功、拒絕與原因、失敗的步驟）。
  只存在於一次對話中，結果寫進日誌。
- **本機程式登記**：本機程式與擴充功能編號的對應，存在目前使用者的設定中；安裝時建立、移除時清除。
- **使用者指定**（既有，009）：設定檔 `[purchase_options]` 中的一行；本 feature 只是新增一種修改它的方式。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 從按下「追蹤這個版本」到面板顯示新版本的數字，在真實願望清單上 ≤ 30 秒（報告步驟目前約 6 秒）。
- **SC-002**: 在一組至少 20 個錯誤或惡意的請求上（FR-014–FR-018 的每一種），100% 被拒絕，設定檔與資料庫逐位元組不變，日誌中有拒絕原因、沒有金鑰。
- **SC-003**: 每次指定或改回後，設定檔與按下之前相比只差那一款遊戲的一行；在含註解、空行、其他區段與其他指定的設定檔上驗證。
- **SC-004**: 在報告產生、資料檔寫入等每一步注入失敗，設定檔 100% 還原為按下之前的內容（逐位元組相同），既有報告與資料檔不變，已保存的正式紀錄保留。
- **SC-005**: 對同一份資料，從面板指定的結果與「手動寫同一行再執行 `report`」的報告與擴充功能資料檔一致（除了產生時間）。
- **SC-006**: 沒有安裝本機程式時，011 現有的端對端檢查全部通過；擴充功能發出的網路請求仍為 0。
- **SC-007**: 背景更新進行中按下按鈕，1 秒內收到「背景更新進行中」的說明，且不影響背景更新的結果。
- **SC-008**: 單按一次後不再按、或由頁面程式觸發的點擊（各至少 5 種方式），送出的請求 100% 為 0。

## Assumptions

- 只有使用者本人在這台 Windows 電腦上使用；擴充功能以開發人員模式載入（011），編號由 manifest 的 `key` 固定（plan 決定 D1）；
  專案資料夾搬家後需要重新安裝本機程式。
- 重新產生報告用現有資料，不重新抓取價格；所以面板上的現價是最近一次每日更新時的價格（011 已顯示資料時間）。
- 指定生效的版本，美國區價格歷史在下一次每日更新才取得（009 FR-004）；第一次重新產生的報告照 009 現行方式處理。
- 報告的時限（60 秒）是使用者體驗上的預設值，可在 plan 中依實測調整。
- 009 的指定規則、模型與決策規則都不變；這個 feature 不需要回測比較（憲章 IV）。
