# Contract: HTML 報告（feature 003）

報告是 `steamsage.decision/1` 的呈現（憲章 VII）。它只讀契約的 dict，不匯入 `steamsage.forecast` 或 `steamsage.decision`，也不做任何計算。
數字格式化只限千分位與百分比，例如 `0.537` 顯示為 `54%`。
（2026-10-22 稽核補記：005 起決策輸出升為 `steamsage.decision/2`，報告讀 `/1` 或 `/2`（`report/html.py`），見 [005 contracts/decision-output-v2.md](../../005-waiting-cost/contracts/decision-output-v2.md) 與 [report-html-v005.md](../../005-waiting-cost/contracts/report-html-v005.md)。）

## 結構

1. **頁首**，依序：
   - 標題
   - 分析時間（台北時間）、資料截止時間
   - 模型名稱與版本、規則名稱與版本
   - 偏好：折扣差距、上下限、即將到價的範圍，標示「使用者偏好」
   - 資料更新狀態：`data_refresh`，不是 0 時醒目顯示
   - 比較基準：沒有時顯示「沒有前一天或更早的紀錄，無法比較」；版本或偏好改變、略過的紀錄也在這裡
   - 各組款數，可以點擊跳到該組
   - 固定提示：
     - 「長期最低價可能更低：目前的模型無法預測比過去更深的折扣」
       （2026-10-22 稽核補記：已被 004 research R9 與 [004 contracts/model-api.md](../../004-deeper-discount-model/contracts/model-api.md) 取代）這句改由模型的 `deeper_caveat` 提供，經決策的 `notes` 顯示，措辭依模型；需要引用數字（`{now_deeper_within_12m}`）卻沒有這個組合的規則回測時，整句省略。
     - 「價格指標準版本（通常是一般版），不含豪華版等套件」
       （2026-10-22，014 T077）改成「價格指 Steam 商店預設的購買選項（通常是一般版）；在設定檔 [purchase_options] 指定了版本的遊戲，指那個版本。」：
       006 起價格跟著 Steam 預設的購買選項（可能含 DLC），009 起可以指定豪華版等版本，舊句子對這些遊戲是錯的。
     - 規則回測的到價率與範圍，例如「台灣區、12 個月內」
     - 「願望清單遊戲比較難預測」
       （2026-10-22 稽核補記）實際上這句不是獨立的提示，而是接在規則回測那一句的最後（「願望清單的遊戲比回測資料集的平均更難預測。」）；這個組合沒有規則回測數字時，那一句改成「甜蜜價規則尚未以現行模型與規則回測：本報告不引用任何準確率。」，這句也不出現（`report/html.py` 的 `_backtest_note`）。

   > 2026-10-22 稽核補記：實際的頁首順序（`report/html.py` 的 `_header`）：標題 → 分析時間、資料截止、模型與規則版本（007 起加非季節模型）→ 橫幅，依序為預覽（005）、資料更新提示（`data_refresh.note`，update 代碼為無、0、5 時沒有）、特賣行事曆提示（012）、參考資料集提示（014）、「本次紀錄未保存…」→ 偏好 → 比較基準（預覽時不顯示）→ 各組款數（010 起加組合包）→ 固定提示（決策的 `notes`、價格指的版本、規則回測一句）→ 名稱篩選框。
2. **名稱篩選框**：輸入文字即時隱藏不符合的遊戲，不分大小寫。
3. **分組**，依序為現在買、即將到價、繼續等、低信心、無法預測。
   - 每組是一個可收合的區塊，標題有款數與該組的規則回測到價率。
   - 低信心組的標題寫「回測中只有約 N% 在這個時點前到價，僅供參考」。
4. **每款遊戲一列**，可展開。
   - 摘要列：
     - 名稱，連到 `https://store.steampowered.com/app/<app_id>/`
     - 現價與折扣
     - 甜蜜價與折扣
     - 甜蜜時點：名稱，加上「官方」或「預估」
     - 到價機率
     - 長期最低價（2026-10-22 稽核補記：規則 2.0.0 以後（含 3.x）的 P_min 只看 12 個月，這一格與偏好說明改叫「12 個月內最低」；只有規則 1.0.0 仍叫「長期最低」，004 research R5）
     - 標籤：低信心、現價可能已變、原價不一致、上限／下限生效等
     - 變動標示：顯示「上次：…」
   - 展開後：原因條列、等待對照表（時點、折扣、價格、機率）、現價的來源與確認時間、日期範圍。
   - 無法預測的遊戲只顯示狀態與原因。
     （2026-10-22 稽核補記）實際上只顯示 `status_reason`，不顯示狀態代碼；`decision-error` 的原因是原始例外文字（`例外類別: 訊息`）。006 起名稱旁還有追蹤版本的說明，009、010 之後展開時另有其他版本表與組合包提示（有的時候）。

## 保證事項（以測試驗證）

1. 每款遊戲恰好一列，位在 `group` 對應的區塊（SC-002）。
2. 顯示的每個台幣金額、折扣、機率、時點名稱都等於契約中的值（SC-003，測試逐一比對）。
3. 所有來自契約的文字都經過 HTML 跳脫；名稱中的 `<script>` 只會顯示成文字（FR-028）。
4. 不引用任何外部資源：沒有 `http(s)://` 開頭的 `src` 或 `href`，只有 Steam 商店的連結，而且只是超連結（FR-027）。
5. 同一份契約產生的報告完全相同。
